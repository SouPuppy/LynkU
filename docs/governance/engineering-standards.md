# 工程与代码规范

状态：目标规范；工具安装和 CI 接入属于 R1/R7，当前不是已经存在的检查能力。

## 技术选择与复杂度预算

- 单仓库采用 npm workspaces，沿用 npm lockfile；不同时引入第二套包管理器。
- 原生小程序 + TypeScript、CloudBase 部署边界保留；业务包不依赖平台。无需为本轮引入微服务、独立 HTTP 服务或依赖注入容器。
- 根安装与各云函数独立产物依赖必须可复现；本地 Node 工具版本、TS 版本、云函数运行时分别记录，不能认为本机能跑就等于云端支持。
- 工具类别固定为严格类型检查、统一格式化、类型感知静态检查、真实依赖图检查、行为测试和构建验证。具体库和版本由 R1 在兼容性试验后选择并锁定；每类只保留一套主工具，不自研已有成熟工具能完成的通用框架。
- schema 库选择以小程序运行兼容性、错误表达、类型推导、打包体积为准；构建器需证明共享代码实际进入小程序/单云函数产物。试验结果形成一份简短 ADR，不无限比较候选。
- 当前 `node:test` 能覆盖用例时继续使用；需要更换测试工具必须说明它解决的具体缺口及旧测试迁移方式。

## 语言与类型

- 新写的业务、应用、适配器和测试使用 `.ts`；工具仅在宿主加载限制等有证据的场景保留极小 `.js/.mjs` 引导。WXML/WXSS/JSON 不为语言统一而替换。
- 基础配置开启 strict；新模块同时开启 noUncheckedIndexedAccess、exactOptionalPropertyTypes。Node 与微信全局类型分项目注入，平台无关包不继承它们。
- 对公开函数显式声明契约；实现局部类型依赖推导，避免重复抄写 schema。使用判别联合表示成功/失败、匿名/非匿名、会话/请求状态，避免许多互相矛盾的布尔值。
- 外部输入使用 unknown，经 schema/守卫校验；禁止通过 any、双重断言、全局 ts-ignore 或排除目录来伪造迁移成功。
- null 表示明确无值，undefined 表示缺省/未提供，按协议使用；数值 0、空字符串不能一律被 `||` 当成错误或缺失。
- 业务时间和随机 ID 通过能力注入，以支持可重复的并发、过期与重试测试。

## 命名、文件与风格

- TypeScript 标识符采用 camelCase，类型/PascalCase，真正全局不变常量可 UPPER_SNAKE_CASE；新类型不加无意义的 I 前缀。
- 内部对象使用 camelCase；旧接口/数据库 snake_case 通过映射兼容，禁止为美观全库重命名。
- 文件/目录以语义明确的 kebab-case 命名，框架路由文件保留平台规则。测试用 `*.test.ts`，同模块单测就近放置；跨模块测试放 tests。
- 沿用两空格、单引号、无分号的 TS/JS 主风格，由选定格式化配置最终统一。UTF-8 与换行配置纳入仓库；新增格式化规则先限定新模块，再单独整理旧模块。
- 跨包使用公开导出，包内部用局部路径；禁止绕过导出表深层访问。导出表不自动导出所有内部文件，不为方便建立循环 barrel。
- 文件长度是拆分提示，不设机械拆分指标。拆分依据是职责、状态所有权和可独立验证的规则。
- 注释解释约束、取舍和异常行为；不注释显而易见的语句，不留下无负责人/退出条件的 TODO。

## 前端状态与 UI

- 页面只绑定输入、生命周期、导航与渲染；feature 负责业务流程，platform 负责 wx 调用。领域规则中不调用 setData/showToast。
- 请求携带会话代际、页面生命周期或查询版本，所有私有响应在应用前验证仍然有效。仅在 poller 检查一次不足以保护资料更新等其他请求。
- 登出先使代际失效，再停止任务、清理内存与私人缓存、导航；存储异常不应阻止内存状态失效或其他订阅者清理。
- 本地持久化使用版本化、按账户隔离的键和恢复协议。编辑草稿不要依赖 onUnload 的网络调用保证保存。
- 轮询有单飞、停止、错误退避、前后台恢复与所有者；不能同一页面/角标重复启动无上限轮询。调度频率与失败策略是配置，不散落魔法数字。
- 列表与分页状态处理旧请求覆盖、新旧页去重、空/错误/加载/陈旧数据；表单处理提交中和明确成功，不能全靠点击防抖保证幂等。
- 保留现有视觉系统，集中颜色/间距/字体 token；布局修复验证长文本、键盘、安全区域、字体放大和低网速状态。
- 界面不展示内部模块名、云函数部署排错信息或原始异常；开发诊断保留在日志及文档。

## 服务端与错误

- 入口统一完成协议校验、可信身份获取、权限策略、请求日志和错误映射；每个 action 都应在动作注册表声明策略，默认拒绝未知 action。
- 数据库操作只在适配器；业务定义语义窄的 port，不暴露通用 query/collection 逃生口。
- 外部 I/O 设置超时；重试只用于允许的幂等操作，并有次数/时间上限与退避。不要重试明确的权限、输入或幂等冲突。
- 事务回调可能重跑，不放邮件发送、不可逆外部请求或随机新增 ID；必要 ID/请求摘要在合适边界固定。
- catch 必须映射/上抛/记录可恢复状态；允许明确说明的最佳努力 UI 清理，但不得静默丢失用户内容。
- 删除、计数、批量更新、审核、资料投影的权限和并发语义由测试证明，不从当前源码形状推断正确性。

## 依赖、配置与安全工程

- 区分客户端可见配置、服务端配置、秘密；客户端构建中不能含秘密。环境参数有 schema 和启动校验，不在代码里多处硬编码。
- 第三方依赖记录用途、版本、许可证及引入范围；生产 SDK 不能用 latest。兼容验证后再升级，不在重构中无理由追逐所有最新版本。
- 基础库版本、渲染器设置和云端 runtime 是支持矩阵；现有配置写着 Nodejs16.13，本轮只将其记为需要核实的事实，不推断线上实际运行版本。
- 私有请求、管理和内部作业各自授权。输入大小/频率有上限；不存在资源与禁止访问的响应需避免不必要的身份枚举。
- 依赖审查、秘密扫描和产物检查接入质量门槛；扫描例外必须有范围、理由和到期条件，不以全局忽略消除告警。

## 变更与评审

一个可评审切片同时带契约、实现、行为验证与必要迁移说明。目录搬迁、格式化和产品行为变化尽量分别提交/记录，但不为形式拆成无法运行的中间状态。

每批说明：解决什么问题、哪些入口受影响、依赖方向是否保持、状态如何迁移、如何验证、是否需云端/设备补验。旧源码模式测试若阻碍结构调整，用等价或更强的行为测试替换，不能直接删掉保护。

用户已有工作不属于可删除遗留。实施开始记录基线差异；新增代码经过验证才纳入迁移完成状态。
