# 质量与验收门槛

状态：目标验收规则。现有本地检查为 `npm run check`，最新实际结果见[状态表](../plans/refactor/status.md)；测试数量不是迁移目标。

## 四类证据

| 门槛 | 证明范围 | 不能推导 |

| G4 设备与发布演练 | 页面、生命周期、分包、关键流程、回滚 | 未定义的法律/运营要求已经满足 |

## G1：可执行结构约束

GitHub Actions 的 [verify workflow](../../.github/workflows/verify.yml) 在 push 和 pull request 中执行 `npm ci --ignore-scripts` 与 `npm run check`。它不持有部署或云端凭据；云端/设备验证仍属于 G3/G4。

- 客户端源码全部使用 TypeScript；架构检查拒绝 `apps/miniprogram/` 下新增 `.js` 源文件及 `any`、双重断言和 TypeScript 忽略指令。全部新业务 TS 严格检查通过；禁止通过 excludes、any、全局忽略减少被检查范围。
- 客户端不直接初始化 CloudBase 数据库或调用集合 API；数据访问必须经由类型化云函数服务，避免私有集合、匿名身份和权限规则被页面绕过。
- `wx.cloud.callFunction` 仅允许在 `services/cloud.ts` 出现；页面、组件和业务服务经由该统一调用器获得错误转换、会话约束和响应校验。
- 格式/静态检查、包导出与依赖图检查通过。domain/feature 直接调用平台 SDK、跨模块深层导入、循环依赖的违规样例必须被拒绝。
- 当前 `tooling/architecture` 使用 dependency-cruiser 解析真实导入图（包含类型与 CommonJS 依赖），并检查平台全局访问；`tests/architecture.test.mjs` 以故意违规的临时工程验证规则会失败。旧 services/common 属于明确的迁移区，不豁免已经迁移的 features/server/contracts 边界。
- 客户端主包/聊天分包构建成功，共享运行时代码实际可解析；服务端/秘密配置未进入客户端产物。
- 每个云函数独立产物包含入口和必要依赖；解包后的导入可解析，不依赖仓库根 node_modules 或未上传文件。
- 从干净依赖安装得到可重复产物/清单；生成物没有被当成手工业务源码维护。
- CI 对当前命令执行，失败返回失败；不允许 catch 后输出成功或有意过滤掉失败测试。
- 文档链接、manifest 与当前接口/部署入口一致。
- `cloudbaserc.json`、`project.config.json` 与客户端运行配置中的环境/AppID 标识一致，质量门禁拒绝漂移。
- 云函数公开错误码必须在共享 contracts 中声明，根检查拒绝两者漂移。
- 每个云函数 action 必须与统一授权策略一一对应；检查拒绝无策略入口和失效策略。

## G2：必须具备的行为证据

| 验收 ID | 场景及预期 |
|---|---|
| A01 会话 | 启动自动恢复/建立微信账号；未认证微信账号为游客；并发身份请求去重；既有账号和认证保留；身份失败可浏览并重试；清理会话/账号更换后拒绝迟到身份结果 |
| A02 权限 | 每个 action 覆盖游客/无账户、未认证、已认证、非所有者及适用管理员；私信/草稿/通知直接调用也不能绕过认证与资源授权 |
| A03 隐私 | 对所有匿名 DTO 注入嵌套身份字段，实际响应仍无真实身份；公开资料无邮箱/验证码；错误、日志也不泄露 |
| A04 会话隔离 | 同一对用户的普通会话、多个匿名来源分别可读可写；历史、同步、标记已读和未读计数互不污染；第三人请求拒绝 |
| A05 游标 | 同时间超过两页、分页期间更新、快照到增量交接、重复页、半途失败、过期游标：无永久遗漏；游标只随成功应用前进 |
| A06 目录与未读 | 超过旧 200 条扫描范围的会话仍可访问；并发 send/markRead、重复已读、多个设备后计数与基准事实一致 |
| A07 幂等 | 提交成功但响应丢失后重试，只存在一个资源/副作用；同键异负载冲突；不同用户同键互不影响 |
| A08 内容一致性 | 发布/审核/移动分类/删除与评论并发下，计数等于事实；重复删除不重复减；父评论/帖子失效后不可继续发布回复 |
| A09 补偿 | 通知消费失败、重复事件、乱序资料事件、工作者重启后可恢复且不重复通知/覆盖新资料；读取不触发全量修复 |
| A10 编辑 | 保存中继续输入、切换草稿、发布响应丢失、清理失败、离线退出恢复，不丢较新文本、不重复发布、不跨账户恢复 |
| A11 生命周期 | 登出/换账户/页面隐藏销毁使私信、角标、资料更新、编辑请求失效；存储异常不能阻止清理；停止后无新轮询 |
| A12 认证与配置 | 邮件暂停时不发邮件、不创建验证码；旧认证保持；非法配置/权限查询故障不放行；客户端开关不能打开服务端认证 |
| A13 迁移 | 空库、旧数据、脏数据、超页数据、并发新增、中断重跑均可核对；索引或前置条件缺失时明确失败 |
| A14 兼容 | 旧客户端协议到新实现、新协议、功能缺失服务器、旧分享链接行为均可验证；隐私修复不被旧接口绕过 |
| A15 错误与资源 | 网络超时/超额/服务故障不伪装成功；有界分页、退避、请求合并；无未处理 Promise 拒绝或无限后台循环 |

优先构造能够在旧缺陷实现上失败的测试。纯规则用单元测试，关键流程通过用例与入口测试断言可观察输出和持久化副作用。只 mock SDK 边界，不把被验证业务整个 mock 掉。

假数据库不能证明真实并发隔离；本地测试应明确模型假设，G3 用真实竞争补验。计时器/时钟可控，测试不用长时间真实 sleep。

## G3/G4：平台与设备

- 隔离环境中从 manifest 建立/核对集合、权限、唯一索引与组合索引。客户端直连私有集合失败，受授权接口成功。
- 验证云 runtime、SDK、事务冲突处理、批量更新上限和查询语义；故障注入检验幂等、补偿和回填重启。
- 旧版到新版升级及支持窗口内回退演练；真实回退后仍能读取兼容数据，不能只演练代码替换。
- 开发者工具及真实设备覆盖冷启动/分享直达/前后台/弱网/键盘/滚动/分包进入；至少记录实际覆盖的平台和版本，不声称全机型通过。
- 已认证测试账户须来自隔离环境受控 fixture；不能修改生产用户认证状态来跑测试。

## 性能、成本与可观测性

R0 记录可取得的基线：构建包体、轮询频率、每流程调用/查询数、分页规模、代表数据集。没有线上数据时使用明确标注的合成样本。

静态要求：所有交互请求有界；评论不周期性全量拉取；会话列表不固定窗口估算；资料和通知不形成随列表项线性增加的无界查询；后台隐藏/退出停止轮询。R1/R3 确定具体批量与超时预算并纳入配置。

性能验收记录冷/热调用、p50/p95、错误率、数据量、并发量和测试环境。目标容量/SLO 的数值由测量与支持环境确定并在 R7 固化；不可凭空承诺线上承载能力。引入依赖导致包体、查询成本明显变化时解释原因并验证可接受。

覆盖率可以定位盲区，但不能代替 A01–A15；不设置可以靠无意义测试凑出的全局完成百分比。缺陷修复至少覆盖其失败路径和相邻权限/并发场景。
