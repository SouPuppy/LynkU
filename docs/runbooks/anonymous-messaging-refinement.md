## 人工本地审核

1. 四种本人／对端身份组合分别进入聊天：标题应显示合法对端；只有本人匿名才强调原身份说明。全局匿名偏好开启后，旧昵称会话仍显示昵称身份。
2. 消息页空列表驻留、新通知已有缓存后切回标签：前台周期摘要刷新后列表跟随。已读后故意延迟旧请求，红点不得被旧值恢复。
3. 发送后断网／切后台：原操作保留，回前台只确认；点击重试不会生成第二条。正文前后空白编辑不会修改原待确认消息。存储失败不会先发送后丢失重试编号。
4. 未读超过 30 条时定位首条未读；阅读旧历史时新消息不抢滚动位置。滚动进入视口前不标记已读；前后台往返保留已加载历史和输入。
5. 屏蔽后重进原会话，及设置 → 屏蔽记录：可恢复与撤销本人操作。另一个匿名通道不出现同人屏蔽标记；另一账号不得撤销此记录。多个独立操作逐个撤销，不合并匿名别名。
6. 匿名帖子改显示昵称会明确确认；拒绝后保留正文与匿名。编辑器内匿名切换不修改全局开关；本人匿名内容下默认匿名回复。
7. 微信开发者工具及 iOS／安卓验证多行输入、键盘高度、安全区、长文本、可见范围观察器、首条未读滚动和底部匿名色块。现有本地模拟不代表真机通过。

## 配套切换

需要同时更新客户端及 messages／comments 云函数，建立 schema 中新增的 `messages(conversation_id,to,status,sync_sequence)` 索引和 `messaging_block_operations(owner,active,_id)` 私有集合索引。独立函数产物只上传 dist/cloudfunctions；本地编译通过不能替代真实索引和事务验证。

维护窗口内停止旧读写、通知消费者及相关资料投影，保存现行产物和数据备份。以下工具默认只读并保存本机备份；参数必须使用 config/project.json 的实际环境，不接受隐含切换：

```powershell
node --import tsx tooling/migrate-notification-identifiers.ts --environment <当前环境>
node --import tsx tooling/migrate-notification-identifiers.ts --blocks --environment <当前环境>
```

逐份审核输出备份路径、数量及 SHA256，再在已停止读写的维护窗口执行对应 apply：

```powershell
node --import tsx tooling/migrate-notification-identifiers.ts --environment <当前环境> --apply --maintenance --backup <通知备份路径> --sha256 <通知备份SHA256>
node --import tsx tooling/migrate-notification-identifiers.ts --blocks --environment <当前环境> --apply --maintenance --backup <屏蔽备份路径> --sha256 <屏蔽备份SHA256>
```

通知迁移先幂等建立新文档，合并已读，再条件删除旧编号并读回；不重新生成 outbox 事件、不增加未读。迁移失败保留备份及新旧状态，可在相同备份上重跑；源数据在审核后变化时拒绝继续。通知临时双份只允许存在于停读写窗口。

旧屏蔽缺少来源通道时，用备份中固定的随机不透明标识生成“历史屏蔽记录”，保留原 blockedBy；不根据昵称或匿名来源猜测真实对方。不需要还原对端身份即可通过本人操作记录撤销。已有通道操作保留其编号，操作记录和 block 状态均读回核验。脚本日志仅含计数、备份位置和摘要；备份包含私有数据，不提交仓库或公开分享。

部署一致版本后验证旧通知编号零残留、已读总量与未读总量、屏蔽状态及指定账号保留，再恢复消费者。若失败，先保持维护状态，按备份恢复一致的数据和产物；不能把旧泄漏编号重新开放给客户端。本次真实上线前只读盘点及备份确认通知和屏蔽集合均为空，因此无需执行旧记录迁移；迁移脚本写入流程仍只有本地模拟证据。
