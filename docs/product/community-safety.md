## 2. 已作出的产品决定

1. **身份与隐私分开。** 微信仍是唯一基础身份；学校邮箱仍是权限升级。新访客在首次隐私告知前不持久建立业务资料，确认后自动完成微信账号初始化，不出现“微信登录／游客登录”二选一。原账号识别与认证保留，不能把迁移当作用户已同意新条款。此项是为隐私保护修订初始化时序，不是新增登录体系。
2. **先浏览，互动前明确同意。** 拒绝／关闭告知可继续公开浏览。协议不预勾选；拒绝同一版本后不在每页重复弹。社交发布、资料修改、私信发送必须有服务端有效的协议／隐私版本凭据，不能只检查本地勾选框。举报、申诉、删除本人内容、注销及必要权利请求不被学校认证或禁言拦住。
3. **默认自动发布，不等人工审稿。** 帖子、评论、昵称均只做微信规则要求的自动文本安全检查，明确通过后直接提交；全部文本都检查。review／risky 不转人工队列，提示修改；超时、额度耗尽、异常返回不公开新内容。现有本地词表只能辅助，不能替代微信结果。
4. **编辑失败保留原公开版本。** 当前请求的不可变文本通过自动检查且版本仍匹配，才原子替换旧公开内容；失败保留旧版和本人修改草稿。不新建需要管理员批准的候选库、待审发布任务。已下架内容不因新请求通过而自动恢复。
5. **私信检查后发送。** 私信不建立会在几小时后自动送出的待审队列。检查无明确通过就显示未发送，保留本人输入；重新发送由用户主动操作。同一次网络重试不得重复发出。
6. **举报后才处理个案。** 举报收到即生成回执，但不按数量自动封人或下架。日常发布不消耗人工审稿时间；只为真实投诉、申诉、严重风险保留受限处理能力。明显严重风险可先采取临时保护措施，并补充理由与复核。
7. **保护匿名。** 普通用户、管理列表和默认案件页均看不到匿名真实身份。处罚由服务器定位账号，不增加“查看匿名者真实身份”按钮。匿名也需遵守社区规则，不承诺监管依法调取时绝对不可追溯。
8. **拉黑有服务端效果。** 拉黑阻止同一账号从其他匿名来源继续发私信；界面不揭露跨来源关联。保留既有聊天历史，解除只取消用户自己的屏蔽。反复尝试多个会话仍可能形成行为推测，不承诺绝对不可关联。
9. **注销是真实关闭。** 确认后立即停用写入并开始清理，无强制冷静期；重新加入要建立新业务账号、重新学校邮箱认证，不继承旧会话和角色。清理本地会话不是注销。
10. **文案必须跟实际一致。** 页面能写“已删除”的前提是对应清理成功；能写“已处理”的前提是有真实处理结果；不能写“绝对安全”“已通过全部合规”“一切责任由用户承担”。

资料门槛只限制普通公开资料变更；依法必要的更正、撤回和删除可经受限隐私请求处理，不能逼用户先同意新条款。重新加入不恢复旧会话和认证，但同微信仍有效的处罚及他人屏蔽在必要保护期内继续生效，防止立即注销重建绕过；不承诺能识别不同微信账号。对已注销对象的最小防滥用关联最多保留 12 个月并按届期／复审规则清理，不秘密无限保存完整账号。

### 设置页信息顺序

账号资料（学校邮箱、昵称）→ 安全（私信与屏蔽、我的举报与申诉）→ 隐私（个人信息与同意、注销账号）→ 关于与规则 → 清理本地数据／清理本地会话。公共的关于、规则、投诉邮箱移出 `user` 条件渲染，不能被未登录提示盖住。

## 4. 同意、版本与权限

保留四种独立事实：可信微信身份、学校认证、对当前必要条款的接受、当前账号限制。任何一个都不能代替另一个。

| 场景 | 首版处理 |
|---|---|
| 从未有账号，无有效隐私凭据 | 公开浏览；仅瞬时处理提供服务所需的可信运行上下文；不先写 users 再补同意，不开启 traceUser 等非必要追踪 |
| 新用户主动接受基础隐私告知 | 服务端保存版本与目的凭据，与账号建立同一可重试流程；自动建立未认证微信账号 |
| 既有账号无协议记录 | 保留原账号和认证，不回填虚构同意时间。必要的本人权利仍可访问，新互动前补充确认 |
| 接受用户协议／社区规范 | 记录各文档版本、全文摘要、服务器时间、账号代际、目的和来源；不记录整段设备指纹作为“证据” |
| 政策实质变更 | 新目的、新类别、第三方或保留期变更先告知，必要时重新同意；旧凭据只支撑旧范围，不自动扩大 |
| 修错别字／排版 | 保持法律版本，单独内容修订记录；不为没有实质变化的修订反复打断使用 |
| 拒绝更新或撤回 | 停止以该同意为基础的新处理，解释具体受影响功能；公开浏览、删除、申诉和注销继续可用，不撤销学校认证来惩罚拒绝 |
| 微信平台隐私授权 | 通过官方隐私 API 与后台隐私指引配套；只在真正调用相关能力时触发。自定义勾选不能伪造平台授权，也不等于自建后台全部处理已有合法依据 |
| 邮件处理涉及境外 | 发送新验证邮件前独立展示境外接收方、用途、字段、地区、权利联系，记录必要的单独同意；拒绝不发邮件，已有认证保留 |

完整接受记录只由服务端生成。客户端提交用户选择及精确文档版本，不提交任意同意时间／角色／认证。不同意时不自动勾选、不通过继续浏览推定接受、不让本地旧缓存绕过服务端。

无服务端有效绑定时始终需要明确的初始化确认，包括关闭标记到期／被删除后的访问；客户端遗留的同意记录不得自动建立新账号。此规则让 12 个月关闭标记到期后仍不会意外复活账号。不是新增登录选项，确认后依然自动使用当前可信微信身份。

账号初始化的必要处理依据、第三方身份链能否满足实际平台账号实名要求，在最终资料核对中确认。微信 OPENID 或学校邮箱不能在文案里被直接等同于已完成全部法定实名核验；不为填这个缺口擅自加收身份证。

## 5. 自动检查与发布体验：不设人工预审

### 状态与用户看到的结果

| 状态 | 作者看到 | 普通读者看到 | 下一步 |
|---|---|---|---|
| submitting | 正在发布／保存／发送 | 尚未看到本次提交；编辑仍见旧版 | 当前请求内自动检查，无人工队列 |
| published／saved／sent | 已发布／已保存／已发送 | 成功提交的版本 | 仍可举报及依法下架 |
| rejected | 本次未能发布，说明需要修改 | 新稿不可见；编辑仍见旧版，除非旧版已下架 | 保留输入，修改后主动重提；误判可提出申诉，但不由管理员代发 |
| unavailable | 暂时无法发布，输入已保留 | 不公开这次提交 | 本次返回失败，稍后由用户主动重试；不后台自动发送 |
| conflict／cancelled | 已有更新／操作已取消 | 不显示未提交修改 | 迟到结果不能覆盖已完成的新操作 |
| unconfirmed | 暂未确认提交结果，请勿重复操作 | 可能已经提交，以查询结果为准 | 复用原 requestId 确认结果，不能谎报未发布并新建请求 |

公开状态继续使用 published／flagged／hidden／deleted，机器调用记录与公开状态分开。微信返回 review 只是本次不能自动通过，不创建 flagged 新公开记录等人批准；历史 flagged 在切换时明确隔离处置，不自动放行。hidden 不是“用户删除”。来源变化传到搜索、主页、通知预览、聊天会话摘要和缓存失效规则。

检查覆盖标题、正文、评论、昵称、私信；保留当前文本上限，官方每次最多 2500 字时完整分段检查并校验边界，不只检查开头。全部分段通过即自动提交，长帖也不另加人工整篇审核；分段不能保证跨整篇语义判断，这是明确记录的技术限制。精确分段、上下文、结果绑定与超时见技术设计。昵称未通过时维持旧值。

头像首版继续现有默认素材；不增加上传入口。服务端禁止新增任意外部头像 URL；旧头像按可信资源清单迁移／审查，不能因前端没有入口就放任接口写入任意链接。

**未发布账号配额约束：** 2026-09-21 官方文本接口文档载明未上架小程序每日 100 次；本项目长帖一次会消耗多次。联调先用合成接口结果覆盖故障与组合分支，真实调用做定量抽样；配额用尽停住新发布，绝不改成词表放行。上线后的额度以控制台及当时官方规则核对，不承诺无限审核能力。[微信文本安全接口](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_msgseccheck.html)

### 依赖与复杂度上限

只保留现有微信／CloudBase、已授权邮件服务；自动安全检查通过微信云调用，不另买审核 API、引入通用大模型、外置消息队列、微服务或人工审稿平台。检查不进入事务，身份／权限／正文版本复验在最终提交中完成。每次逻辑提交有总超时、并发上限、幂等与额度控制，不无限重试。

内容检查故障只影响当次新增／修改／发送，已有内容浏览、本人数据权利、举报和安全设置继续可用。发送邮件故障不影响已有认证账号；公开规则是随包资源，不能要求第三方页面在线才能阅读协议。法律文本不把这一有限平台依赖宣传成“完全离线安全检查”。

## 6. 举报、处置与申诉

举报理由固定为：辱骂／骚扰／网暴、隐私泄露、诈骗／违法交易、色情／未成年人不当内容、暴力／违法信息、侵权／冒充、垃圾广告、其他。说明最多 1000 字；“其他”至少 5 字。不要要求举报人粘贴身份证、学生证、家庭住址。

内容举报只提交来源标识；私信举报从本人会话中选择具体消息。服务端取证，客户端自己填写的作者身份和角色没有效力。非用户、无法登录用户可通过公开邮箱提出投诉；实际核验限于处理诉求所需信息。

管理案件页只呈现：来源及被审版本、具体证据、适用规则、前次决定、当前是否仍生效、需要的处置按钮和记录。不得开放全站用户搜索、任意私信浏览、批量封号或匿名身份导出。

| 处置 | 适用方式与默认边界 |
|---|---|
| 不处理／证据不足／重复 | 记录原因并给举报人结果；不向对方暴露举报人 |
| 下架特定内容 | 正文退出普通读取，计数和通知一致；保留必要案件证据，不能靠客户端隐藏 |
| 临时限制 | 选范围（发帖评论、发送私信、修改资料）及 1 小时／24 小时／7 日／30 日，必填理由；首次轻微问题优先提示改正，严重情况可直接保护性限制 |
| 持续严重违规 | 可选择持续限制，必须给具体事实、理由、复核时间；不能由机器分数直接永久封禁 |
| 申诉撤销 | 撤销对应决定的效果，保留审计；不复活用户已删除内容，不覆盖其后新的处罚 |

申诉从本人处置详情进入，绑定具体决定，说明最多 1000 字。一个未结申诉不重复建案；可以补充说明，已结后有新事实可再申请。封禁账号仍能提交。账号学校认证不因禁言被抹除。

运营目标：立即自动回执；工作台按紧急程度和等待时间排序；严重隐私泄露、未成年人及人身威胁优先处理；普通事项争取 1 个工作日开始处理、7 日内给结果，复杂事项告知进展。它们是本项目服务目标，不宣称统一法定时限。不要求管理员常驻或逐条批准帖子；上线前验证能接收并处理真实投诉。持续出现无法处理的严重风险时采取必要保护措施，不能用“默认不审稿”免除实际投诉责任。

## 7. 防骚扰、未成年人及位置边界

成年人现有收信行为保留，提供显眼的“暂停接收私信”和针对对象屏蔽。关闭接收同时停止发送，避免发出后单方面让对方无法回复；开关变更提示影响，不删除历史。拉黑只影响后续发送资格，不能宣称撤回对方已经看到的内容。

**首版保护模式默认开启**；未确认年龄范围的账户按保护模式处理。自述年满 18 周岁的用户可主动选择普通模式；仅保存 under14／14to17／adult／unknown 及选择时间，不采集生日或身份证，不能把自述标注成实名年龄认证。14—17 岁保留学习讨论和投诉权利，默认暂停私信，不展示未成年人真实年龄／身份标签，监护人求助通过隐私联系渠道处理。

年龄范围放在首次初始化确认同一界面，允许暂不说明并维持保护模式；已知 under14 则不继续建互动账号／发送验证码，转公开浏览与监护人联系。既有账号首次进入相应设置或互动入口补充选择，未知状态采用保护模式，不清空原认证。正常发帖不因没有管理员在线而停住。

已知不满 14 周岁时不继续提供账号互动、邮箱发送或私信；进入监护人联系及删除／限制处理流程。首版不建设儿童社交产品，也不以一行“限成年人”当作已满足未成年人保护要求。发现已有儿童信息时按个案执行必要保护，不能仅封账号继续保留全部内容。

保护模式不是完整未成年人合规的自动证明。社交服务未成年人模式的适用要求、监护人机制及使用时段等，作为正式公开前的专项核验；若实际开放儿童服务则必须另补专门规则和有效监护人授权，不能在此次默认范围内偷偷打开。[未成年人网络保护条例](https://www.samr.gov.cn/wljys/gzzd/art/2024/art_43b2ac59aefd427aabe333df54d68f0a.html)

账号 IP 属地展示采用服务端可信请求来源推导的粗粒度地区，最多境内省级／境外国家或地区；不申请 GPS，不从客户端传入地区获取信任，不展示原始 IP。若运行上下文没有可信来源，记录待接入，不能用学校所在地伪造每个用户属地。匿名场景的展示范围先与平台匿名规则一同确认。[互联网用户账号信息管理规定](https://www.cac.gov.cn/2022-06/26/c_1657868775042841.htm)

## 8. 注销、个人信息副本与本地清理

注销页分两次操作：先展示影响与待处理事项，再由当前微信身份获取短期确认凭据并最终提交。无需再次邮箱验证，不设置加客服、补缴费用、先清空内容等不合理前提。

- 提交成功即显示“账号已停用，数据清理中”，停止新写入、轮询、自动保存及迟到私有响应；失败只显示真实状态，不先宣布注销成功。
- 账号状态 active→closing→closed；故障按检查点重试，不恢复 active。关闭与最终删除／受限保留分别展示。
- 本人帖子、评论和私信正文退出正常服务；保留他人的独立消息与回复结构，使用“内容已删除／对方已注销”占位。通知及会话摘要同步去掉已删正文。
- 清理学校邮箱、验证码、草稿、本人通知、账户缓存和相关队列；服务端保留的个别法律／争议证据移入受限区域，说明理由、范围与期限。
- 重新加入产生全新内部账号与公开标识，重新学校邮箱验证，不能认领旧内容／会话／角色。最小关闭标记的用途及期限必须公开，不称为完全匿名。
- 清理本地会话仅结束当前显示和任务；清理本地数据还会删除本机草稿恢复及搜索记录；注销覆盖服务端。三个动作分别告知后果。
- 离线设备下次连网需清理，无法保证远程删除他人截图或已下载副本。备份恢复必须先重放删除台账，再允许业务开放。

个人副本首版用本人重新确认身份后的结构化分页查看／复制，按账号资料、本人帖子评论、草稿、本人可取得的消息及请求记录分组。提供明确“复制本组数据”能力及页码／游标进度，超页不假装导出完整；复杂或大量副本进入有进度的人工协助请求。不能返回匿名对端真实身份、他人邮箱和内部安全规则，也不新建公开下载链接。

副本游标绑定当前 accountId、账号代际、分组及查询范围；普通分页不是事务快照，标明取得时间，期间发生变化时说明范围并允许重新生成。注销／换账号使旧副本请求和复制按钮失效，未完成的分组不显示“已全部导出”；重新加入不能继续旧游标。可提示先取得副本，但不得将导出完成作为注销前提。closed 只开放必要请求结果，不重新开放旧业务资料。

更正优先走现有昵称／换邮箱路径；指定删除、转移、限制处理和无法自助更正的诉求进入隐私请求，管理员决定后必须通过所属业务能力执行实际改变，不能只写“已处理”。

## 9. 关于页、公开配置与送审边界

“关于 LynkU”显示：校园交流用途、独立运营且非学校官方、真实运营者姓名、联系邮箱、现有备案号、当前版本、四类规则入口。AppID 与原始 ID 用于部署核对，不需要在用户界面堆放。学校邮箱认证只说明控制指定邮箱，不代表学校认可内容／运营者。

公共元数据扩展唯一配置 `config/project.json`；文档版本及正文使用一次构建产物分发，客户端和服务端按相同摘要校验。最终字段包括运营者姓名、支持邮箱、核实后的备案号、政策版本／日期、第三方清单版本。秘密、原始身份映射、审核凭据和 Mailgun 密钥不得放入公共配置。修改配置仍运行现有 `npm run configure`，不能手改生成配置。

开发稿允许明确未定字段；正式发布校验必须拒绝“郑**”“待填写”、空接收方信息、未实现却已承诺的权利功能。现有备案事实保持已完成，只核对展示字符串和后续资料变更义务。

个人主体当前教育类目与真实论坛／匿名社交能力是否匹配，是单独的公开发布条件。代码可以先完成，不能因此宣称协议写好就保证过审；也不通过“审核时隐藏、上线后恢复”规避。确需更改首发产品范围时记录实际取舍，不让实现者偷偷删除用户要求保留的匿名／私信。[微信类目](https://developers.weixin.qq.com/miniprogram/product/material/)；[运营规范](https://developers.weixin.qq.com/miniprogram/product/)

### 直接切换，禁止兼容层

服务端与小程序只保留一套新协议。迁移窗口停止旧写入，保留可核验的账号、认证与内容数据；部署配套新版本后，旧客户端明确提示升级／暂不可用，不转旧 action、不双写、不继续接受旧 OPENID 所有权请求、不用旧词表作为降级放行。移除废弃入口、字段解析和 fallback，并测试它们不能绕过新权限。回退仅限恢复一套一致且安全的代码与数据；无法安全恢复时保持停写，不重新开启有隐私缺口的旧入口。

## 11. 依据与适用说明

本方案是基于现有代码和官方公开资料作出的产品／工程设计，不是法律意见书或审批结论。法律要求与本项目选择分开：协议、真实投诉与数据权利有制度依据；具体页面、交互、保留天数和处理目标是本项目落实方式。

- [应用程序信息服务管理规定](https://www.cac.gov.cn/2022-06/14/c_1656821626455324.htm)：账号、服务协议及投诉等依据。
- [跟帖评论服务管理规定](https://www.cac.gov.cn/2022-11/16/c_1670253725725039.htm)：评论治理、真实后台身份和申诉；不能把前台匿名推导成微信平台必定允许。
- [网络暴力信息治理规定](https://www.cac.gov.cn/2024-06/14/c_1720043894161555.htm)：举报、防骚扰、必要保护及处置机制；拉黑和工作台是本项目的实现选择。
- [个人信息保护法](https://www.samr.gov.cn/wljys/gzzd/art/2023/art_3ef1e889c1e644d4b65b5f5c7f432386.html)与[网络数据安全管理条例](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)：告知、同意、权利与删除／受限保留；具体数据表和时序由技术设计落实。
- [微信隐私授权说明](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)：平台隐私授权与自建协议记录分别实现。

更完整的监管、供应商、依赖和运行风险证据保存在 [2026-09-21 审查快照](../audits/launch-readiness-2026-09-21.md)，不复制为第二份活动待办。
