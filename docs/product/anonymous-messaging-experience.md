# 匿名参与与消息体验设计

日期：2026-09-23。状态：**已按保留原 UI 范式的边界进入本地实现交付，待人工审核；未部署、未完成真机视觉验收**。实际实现、验证与迁移边界见[审核说明](../runbooks/anonymous-messaging-refinement.md)及[唯一状态表](../plans/refactor/status.md)，下文保留设计依据，不以提案代替实现证据。

最新设计约束：**沿用现有 UI 范式，只做局部精修。** 保留导航名称与层级、页面布局、组件形态、蓝白基调、字号和间距。此前交互示意的改版幅度过大，不作为实施样式参考；撤回导航改名、列表重排及成套视觉替换建议。隐私与消息逻辑的深度调整不要求同步重做界面。

本方案在 v1 上精进身份表达、聊天连续性和提醒一致性。现行行为已同步到[行为契约](behavior-contract.md)，修复前证据保留在[聊天与通知诊断](../diagnosis/chat-and-notification-review-2026-09-23.md)；实施状态只记录在[重构状态表](../plans/refactor/status.md)。

## 1. 产品目标与边界

核心体验是：**用户始终知道这次以什么身份说话；匿名方不会被系统重新关联到公开账号；消息到了能看见，发出后知道结果。**

用户只需要理解“显示昵称”和“匿名参与”。微信身份、学校认证、服务端通道与请求编号由系统处理，不变成额外账号、模式层级或设置步骤。匿名切换是新发言的默认选择，不是换账号，也不改变认证权限。

保留 v1 的微信基础身份、学校认证、帖子与两级评论、文本私信、互动通知、草稿、举报与屏蔽方向，以及现有服务端权限、独立匿名会话和消息幂等基础。此次不加入群聊、语音、关注、匿名好友、匿名主页、固定匿名人格或第二套消息后端。

“保护匿名”首先是服务端和数据协议的责任。深色结构、匿名图标和提示文字用于表达真实状态，不能代替脱敏或掩盖服务端未确认的身份。

## 2. 信息结构：沿用现有入口与布局

保留主导航“首页／私信／我的”、页面标题“私信”及内部“私信／系统消息”标签，保留原有顺序、路由和页面骨架。下文的“互动通知”描述业务类型，不代表重命名标签。信息完善优先使用已有标题、预览、身份说明和异常提示位置。

| 页面 | 主信息与操作 | 次要信息与操作 |
|---|---|---|
| 首页 | 浏览、搜索、进入帖子、发布 | 保留现有操作入口，不新增全局身份选择器 |
| 私信—私信 | 全部普通及匿名会话，最近消息、时间、未读 | 沿用现有列表和刷新操作 |
| 私信—系统消息 | 评论、回复，行为对象摘要与未读 | 点击定位目标；失效说明；重试原失败操作 |
| 聊天详情 | 对方身份、消息流、当前本人发送身份、输入 | 保留举报、屏蔽入口位置；在现有提示位置表达异常 |
| 我的 | 本人账号、学校认证、本人内容与草稿 | 匿名参与偏好、私信与屏蔽、其他现有设置 |

聊天使用一套混合列表，按会话最新活动排序；不再让用户先选择“普通收件箱”或“匿名收件箱”。正常浏览、翻页不把会话自动标记已读。

保留现有列表行的头像、昵称、时间、预览和未读位置，不新增固定第三行或重新卡片化。匿名会话辨识优先复用昵称位置；本人身份优先在聊天内已有说明位置讲清。匿名对端没有可跳转的真实资料。缺少有效预览时展示相应占位，不能用缓存恢复已删除正文。

导航总角标与现有“私信／系统消息”分区数量来自同一轮协调后的摘要。后台刷新失败时保留已知内容和数量，标记需要刷新；不能把失败当作零未读或空列表。不新增分类。

## 3. 身份规则：偏好、当前行为和历史各自明确

### 3.1 默认选择与冻结时机

| 场景 | 身份来源 | 切换全局匿名偏好的影响 |
|---|---|---|
| 新建帖子、新打开的评论输入、新发起私信页面 | 打开时读取偏好，显示本次选择 | 不在页面已打开后偷偷改变本次选择 |
| 继续草稿 | 草稿保存的身份选择 | 不覆盖草稿 |
| 正在提交或等待发送确认 | 提交时冻结的身份与正文 | 不改变在途请求 |
| 已有聊天 | 服务端确认的本人和对端可见性 | 不改变任何一方身份 |
| 编辑已发布帖子 | 该帖当前身份；保留显式编辑能力 | 不隐式修改；扩大可见范围须单独确认 |
| 已发布帖子、评论、通知、历史消息 | 对应内容或会话的既有身份规则 | 不批量变更历史，不恢复隐藏资料 |

全局入口名称建议为“匿名参与”，说明为“新发帖、评论和新对话默认使用匿名身份”。切换后的轻提示为“新发言将默认匿名”或“新发言将默认显示昵称”，不用“已换账号”。

复用现有匿名选择入口，不在各页面新增一套身份控件。本次选择不顺带更改全局偏好；首条消息成功建立会话后身份固定。网络重试、确认恢复、前后台切换均不是再次新建会话。

打开已有聊天时先确认身份元数据，未就绪期间保留安全占位并禁用发送，不能根据页面路径或全局开关猜测后先允许发送。匿名方真实身份缺失时不回退到账号资料。

新私信页面展示的身份预览也须由服务端最终核验。如果打开页面后来源内容的可见性或状态变化，首条发送不能静默扩大任一方身份暴露范围；应重新确认有效目标和展示身份，保留未发送正文。来源下架时不再从该来源新建，已有会话仍按成员权限访问。

### 3.2 四种对话组合

以下按当前查看者视角表达。聊天中的局部匿名提示只表示**本人在这段对话中匿名**，不要求整块输入区换色。

| 本人／对方 | 标题与对方资料 | 本人发送区 | 对方看到的本人 | 常驻短提示 |
|---|---|---|---|---|
| 显示昵称／显示昵称 | 对方昵称、头像，可进入合法公开资料 | 保留原样 | 本人昵称、头像 | 沿用必要的现有说明 |
| 匿名／显示昵称 | 仍显示对方昵称、头像及合法资料入口 | 原结构配合现有身份说明 | 匿名身份 | 你以匿名身份参与 |
| 显示昵称／匿名 | 匿名会话名，无真实资料入口 | 保留原样 | 本人昵称、头像 | 对方可见你的昵称 |
| 匿名／匿名 | 匿名会话名，无真实资料入口 | 原结构配合现有身份说明 | 匿名身份 | 你以匿名身份参与 |

不使用“双方身份隐藏”概括所有匿名会话。对方匿名不使本人自动匿名；本人匿名也不应遮掉本来合法可见的对方昵称。

身份提示复用聊天中已有说明位置，简短清楚，不为此搬动输入区或新增常驻横栏。必要说明为“对方不会看到你的账号昵称和头像；正文中主动透露的信息仍可能被识别”。不承诺绝对不可追溯，也不在每条气泡重复长篇说明。

全局匿名开启后，打开旧的昵称聊天仍使用正常输入区，显示“本对话仍显示你的昵称”。已有会话没有就地换身份开关；另起匿名私信仍遵循现行独立发起规则，不转换或搬运原聊天历史。

### 3.3 内容编辑与回复不得制造身份关联

保留当前帖子显式编辑身份的能力。匿名改为显示昵称时，必须在提交前单独确认：“保存后，这篇帖子的内容将与你的昵称和头像关联，其他人可能据此识别原匿名作者。”操作使用“继续匿名／显示昵称并保存”，取消后保留正文编辑。确认绑定本次提交快照，网络失败后的同一快照重试不要求反复确认；身份或相关负载重新改变后重新判断。

显示昵称改为匿名可隐藏后续公开投影，但说明“已经被看见、截图或保存的信息无法收回”。不能把它描述为抹除历史关联。既有私信双方的可见性不随来源帖子修改而变化；通知投影不得借机公开原本匿名的互动者。永久锁定已发布内容身份是未来可评估取舍，**不属于本轮已决定的变更**。

用户回复自己匿名发布的内容时，输入默认“以匿名作者回复”，优先保留该上下文的匿名身份。用户显式选择显示昵称时，不同时附加能证明其是匿名作者的“楼主／作者”标记。角色标记仅在合法的同一身份上下文中出现；不能利用标签、链接、通知或作者摘要桥接匿名和昵称身份。

公开个人主页、作者筛选、搜索、分享摘要都不能把匿名内容列为该昵称账号的活动。本人私有管理页可以展示自己的匿名内容，但要有独立权限与展示语义。

### 3.4 匿名会话如何辨认

匿名对端建议显示“匿名会话 · 7K2”一类短码。短码标记当前会话，不是“匿名用户 7K2”的长期人格；它在此会话内稳定，在新会话中独立分配，不能从真实账号推算。

统一匿名图形配合短码、最近消息和时间满足基本区分，不按账号生成跨会话一致头像或昵称。不展示“这是你聊过的同一个人”、关联会话数量或恢复隐藏身份的资料入口。也不为辨认方便默认重新加入来源帖子预览或其他上下文；来源展示须另有明确隐私边界，不能作为视觉装饰直接加回。

## 4. 视觉：浅色阅读面与有含义的结构翻转

保留现有蓝白风格、页面背景、列表、头像、消息气泡和输入区形态。匿名提示优先在用户提出的既有底部 menu 上做局部深色翻转，位置、尺寸、名称和操作不变；不扩展成全站深色主题，也不同时重做发布区和聊天输入区。

沿用现有样式值，仅为匿名结构增加必要色值。实施时检查局部对比度并完成真机验收，不替换全站设计规范。

| 语义 | 建议值／规则 |
|---|---|
| 品牌与常规主操作 | `#1E4D8C`，延续现有蓝色 |
| 匿名结构背景 | `#242A32`，炭灰而非纯黑 |
| 常规阅读背景 | 保留现有 `#F5F5F5`／`#FFFFFF` |
| 主要／次要文本 | 保留现有 `#333333`／`#999999` |
| 匿名结构主要／次要文本 | `#FFFFFF`／`#BBC3CC` |
| 分隔 | 保留现有 `#EBEDF0`；局部深色面按实际需要适配 |
| 错误与未读 | 使用独立语义色；匿名切换不把红点变灰或弱化失败 |
| 间距、字号、圆角 | 沿用现有组件，不另建一套规格 |
| 触控 | 保留操作位置；确有误触问题时局部修正点击范围 |

主导航在全局匿名偏好开启时可使用炭灰背景，选中项白色、未选中项浅灰；关闭时恢复原背景和蓝色选中态。保留现有导航实现及文字结构，不为增加匿名图标改造导航组件。现有匿名开关和行为身份说明共同解释颜色含义。全局颜色仅表示新行为默认偏好，不能覆盖旧会话身份。

颜色同时配合文字和图形，不要求用户单凭深浅猜测身份；此原则参照 [W3C 颜色使用说明](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。实施时普通正文以至少 4.5:1 的文字与背景对比度检查，见 [W3C 最低对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)；本稿不宣称已通过整套无障碍验收。

聊天身份以第 3.2 节的服务端可见性为准，与全局偏好分离。先修正已有身份说明；若仍需色彩辅助，只在原身份提示或既有操作区域小范围强调。输入框、气泡及消息背景保持原设计，对方匿名不使本人区域变成匿名样式。

身份提示、屏蔽、举报和时间沿用现有位置与组织方式，不新增更多菜单或调整时间分组。异常恢复后清除旧警告等行为修正直接作用于原组件。

“我的”保持本人账号与认证信息真实可见，旁边展示匿名偏好。它不伪装成另一账号；账户管理与他人能看到的发言身份应容易区分。

## 5. 聊天交互与关键状态

### 5.1 阅读和输入的连续性

- 第一次进入有未读的会话，优先定位首条未读及“以下为新消息”分界；无未读时展示最新消息。只有服务端能可靠提供该范围时实现精确定位，不用最近 30 条假装覆盖全部未读。
- 用户接近底部时收到新消息，轻量跟随；正在阅读旧记录时保留位置，出现“有 3 条新消息”入口。点击后进入新消息区域；不被定时刷新拉走。
- 加载更早消息保留首条可见消息的锚点；切后台再回来保留历史、输入和阅读位置，用原同步位置追赶，不整页清空重来。
- 多行输入从一行增长至约四行，再内部滚动。与现有服务端正文限制一致，接近上限时再显示字数；空白内容不能发送，换行不误触发送。
- 键盘弹出时输入区始终可见，滚动区域与安全区同时调整；收起后恢复阅读位置。iOS／安卓、不同屏幕和字体大小单独验机。
- 提供文本复制和消息级重试，不扩充语音、图片等输入形态。

### 5.2 发送结果与恢复

| 状态 | 用户看到的反馈 | 处理规则 |
|---|---|---|
| 正在发送 | 本人气泡及弱化进度标记 | 固定正文、身份、通道和请求编号；输入框可开始下一条 |
| 服务端确认成功 | 正常气泡；确认后再显示“已发送”或省略常态文案 | 与返回消息合并，不额外生成副本 |
| 结果待确认 | 原气泡保留，短提示“正在确认发送结果” | 先按原请求查询／对照历史；不能把未知直接当作失败重发 |
| 明确发送失败 | 原气泡旁“未发送，点按重试” | 用户重试原快照、原编号；错误原因适度说明 |
| 仍无法确认 | “发送结果未确认，点按检查” | 可再次核对；需要重试提交时由用户触发并沿用原幂等请求 |
| 明确权限或内容拒绝 | “未发送”及可执行原因 | 不自动重试；用户修改后作为新消息处理 |
| 已读 | 仅真实确认过的本人消息显示“已读” | 不用拉取成功冒充对方已读，不声称未实现的已送达 |

发送操作从输入草稿中独立出来：用户已提交的正文保存在对应气泡状态，不因为在输入框补空格就失去原消息的去重关系。服务器已经收下但回包丢失时，回前台只做确认恢复并合并结果，不能让历史和输入框各残留一份可再次误发的原文。

未确认消息不在后台自动重新发送。自动动作仅限受控确认读取与已成功应用的同步；用户明确点击的重试仍须通过当前服务端权限和安全检查。待确认状态、草稿、已确认消息按账号与会话隔离，清理会话时终止任务；不恢复到其他账号。

### 5.3 已读与异常

聊天已读至少满足页面前台可见、消息成功渲染且进入可见阅读范围。加载历史、后台同步或用户停留在旧记录时取得新消息，都不能自动将那些未展示的新消息标记已读。

复用现有显式消息 ID 的已读接口，按前台实际可见消息收集 ID、分批幂等提交；消息序号继续用于稳定排序与同步，不因为看到更高序号就把中间未展示的消息一起标记已读。无需为此次体验升级新建已读水位模型，也不引入逐字、停留时长或眼动判断。

互动通知以通知卡实际在前台可见为自动已读条件，不以取得一页 20 条为条件。点击通知也可确认该条已读。该规则比现行按页已读更严格，是本提案的有意调整。已读写入失败保留待同步事实，恢复后幂等补偿；旧计数响应不能把已确认读取重新改回未读。

首次加载失败显示错误态和“重试”；有内容时刷新失败保留内容，轻提示“暂时无法更新，点击重试”；翻页失败在页边界重试该页。一次有效同步成功即清除连接异常，即使没有新消息也一样。隐藏、销毁、清理会话后停止对应轮询，迟到结果不得恢复私有界面。

## 6. 提醒：站内先可靠，站外单独建设

站内到达表现是同一事件引起的会话预览、排序、行内未读、分区数量和导航角标共同更新。消息首页驻留时也要收到变化，不能只更新导航红点。

客户端在进入前台、进入或切回相应标签、发送／已读成功、网络恢复及受控周期刷新时协调失效与更新。合并并发读取，以账号代际和请求／摘要版本拒绝迟到覆盖。刷新第一页保留用户已加载的后续内容和阅读位置；不能用不断全量清空列表实现一致性，也不简单缩短所有轮询间隔。

互动通知显示“匿名用户回复了你”或合法可见的昵称，不夹带隐藏账号、可枚举身份哈希或跨来源稳定标识。点击后定位具体评论／回复；源内容删除时显示“这条内容已不可用”。尚未投递的旧事件在投递前核验有效性，避免删除后制造新的空通知；事件时间与补偿投递时间分开，不能把旧互动伪装成刚发生。

**退出小程序后的微信提醒不属于本轮已可用能力。** 未来须核对本 AppID 的实际类目、模板及订阅能力，完成授权、服务端发送和真实回执验证后才展示有效入口。不得提前放一个看似能持续推送的开关。届时优先使用“你有新的私信／互动”一类最小内容，不默认把匿名身份线索和私信正文带到站外；具体字段以真实可用模板为准。不承诺每条、永久或实时到达。

## 7. 屏蔽与隐私底线

屏蔽在服务端阻止同一账号换普通或匿名通道继续骚扰，保留已有历史。界面操作为“屏蔽对方”，确认说明“对方将无法再通过私信联系你，已有消息保留”。举报与屏蔽可分别执行，不把屏蔽误写成撤回历史。

屏蔽成功后，原操作会话和设置中的本人操作记录可以持续显示状态与“解除屏蔽”。该记录仅使用操作当时的合法别名和不透明操作标识；匿名对象不出现真实资料。禁止在其他会话批量打出“已屏蔽同一人”、合并匿名项或显示关联数量。

不提供遍历任意匿名会话查询是否为同一屏蔽对象的能力。解除只从本人有权访问的操作记录恢复，服务端执行当前真实约束，不依靠易丢失的页面布尔值。发送方收到通用无法发送反馈，不揭示隐藏对象与其他会话的关系。账号级屏蔽仍可能被反复发送行为有限推测，不能承诺行为绝对不可关联。

所有帖子、评论、消息、目录、通知、错误、分享预览和必要日志均需显式映射公开字段。公开编号不依赖隐藏身份的可枚举输入。客户端即使被直接调用接口、查看存储或篡改参数，也不能拿到匿名对端账号、学校邮箱、OPENID、真实头像昵称或跨匿名通道的关联标识。

## 8. 最小实现结构

沿用[模块所有权](../architecture/module-boundaries.md)与现有云函数装配，不建立新后端、全站状态框架或“匿名身份服务”。

| 归属 | 本轮收口职责 | 不扩展的职责 |
|---|---|---|
| identity 及既有客户端会话能力 | 可信账号、认证、账号代际；本地匿名偏好的单一入口 | 不代写内容／聊天，不创造第二账号 |
| messaging 服务端与客户端功能层 | 会话双方可见性、目录、发送操作状态、确认恢复、历史与可见消息已读、屏蔽操作记录 | 不依据全局偏好猜测旧会话身份，不跨会话合并匿名对象 |
| notifications | 互动投影、有效事件投递、已读补偿与计数 | 不在列表读取时全表修复，不承担聊天正文状态 |
| 现有客户端应用装配与消息页 | 协调聊天／互动摘要失效及刷新，统一生命周期和角标出口 | 不变成可写任何业务的全局仓库 |
| content／interaction 的既有写入流程 | 草稿身份快照、帖子身份变更确认要求、自己的匿名内容回复及安全作者标记 | 不读取其他匿名内容来推断身份 |
| 页面／通用展示组件 | 按明确视图状态渲染身份、菜单、气泡和异常；上报可见范围 | 不直接用 wx／数据库执行业务规则，不把数据库记录原样渲染 |

会话展示契约至少提供本人可见身份、对端合法展示身份、当前通道显示标识及本人的受控操作信息。具体字段命名在实施时确定，但必须使用明确判别类型和运行时验证，不用“有 anonymousTarget 所以双方匿名”的推断。新会话预览可以表达尚未建立状态，既有会话以服务端保存值为准。

客户端只需要三个范围明确的状态：账号级消息摘要、会话级阅读与同步、单条发送操作。匿名视觉由这些状态派生，不维护另一份容易漂移的主题业务状态。页面复用现有传输入口，业务流程通过窄接口注入网络、存储、时钟和生命周期。

通知公开编号调整、会话展示元数据或屏蔽记录新增均须同批写契约与迁移说明。历史通知需保留已读和事件幂等结果；不得为换编号把旧事件重新投成新未读。匿名修复没有保留泄漏旧协议的兼容义务，但实际迁移要先验证备份与指定账号保留对象。

## 9. 验收场景与推进顺序

按[质量门槛 G1–G4 与 A01–A15](../governance/quality-gates.md)记录证据，先行为后视觉，测试失败路径和真实副作用，不以页面截图或测试数量代替匿名保护。

| 验收场景 | 必须得到的结果 | 证据门槛 |
|---|---|---|
| 四组合分别双账号往返 | 本人提示、对方展示、深浅结构与服务端实际可见性一致 | A03/A04，G2/G4 |
| 匿名偏好开启后进旧昵称聊天 | 保留昵称身份及正常输入区，无静默切换 | A04/A11，G2/G4 |
| 草稿恢复、切偏好、发送中切模式 | 草稿／请求快照不被改写，不产生身份错发 | A07/A10/A11，G2/G4 |
| 自己匿名帖子下回复及显式改身份 | 不通过作者标记、通知或资料页泄漏；扩大可见范围确认有效 | A03/A08/A10，G2/G4 |
| 同两人普通与多个匿名会话 | 历史、短码、未读、已读、缓存不串读，不输出关联 | A03/A04/A06，G2/G3 |
| 注入嵌套身份字段及候选编号比对 | 实际响应、错误、日志和公开标识均不能恢复匿名身份 | A03，G2/G3 |
| 空收件箱驻留、已有互动缓存 | 新消息出现时列表与所有摘要及时收敛，无旧响应恢复红点 | A05/A06/A11，G2/G4 |
| 服务端已提交但回包丢失 | 原气泡最终确认且仅一条消息；恢复不后台自动新发 | A07/A11/A15，G2/G3/G4 |
| 阅读旧记录时收新消息、键盘及回前台 | 位置不跳、输入不被遮挡、不误报未读消息已读 | A06/A11，G2/G4 |
| 刷新／翻页／已读失败及空同步恢复 | 内容保留、重试正确操作、有效恢复清错、已读补偿收敛 | A05/A06/A09/A15，G2/G4 |
| 删除内容后迟到通知 | 不制造新的无效互动，已有通知不恢复正文或隐藏身份 | A03/A08/A09，G2/G3 |
| 屏蔽后重进及跨通道尝试 | 原记录可解除，跨通道防骚扰生效，其他行不暴露关联 | A03/A04/A11，G2/G3/G4 |

建议按可验收切片实施：

1. **身份与隐私**：会话显示契约、四组合、通知编号、身份切换与作者标记保护；补失败后通过的行为验证。
2. **消息可靠性**：摘要刷新协调、发送确认恢复、已读与生命周期、正确重试；保留现有服务端事务基础。
3. **局部交互和视觉**：原位置身份文案、必要的会话辨识、底部 menu 匿名色块、滚动和键盘修复；保留导航、布局和组件范式，覆盖双账号与真实设备。前后对照确认未引入页面重排、全站样式替换或新的操作层级。
4. **未来站外提醒**：仅在平台能力和授权链路实际可用后独立推进，不阻塞前述站内精进。

每片完成运行适用检查、更新唯一状态表，明确 G3/G4 未完成项。需要迁移或设备验证的工作不以本地编译成功代替验收。
