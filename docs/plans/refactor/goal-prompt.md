# 后续长任务指令

使用方式：在此仓库开启长 goal 时使用下文作为任务内容。用户计划使用 **astra medium**；模型与推理档位在启动任务时选择，本文不会自动启动任务或修改设置。

---

请按照仓库已经确定的全面重构方案，持续完成 Lucky 的工程迁移。

先阅读根 AGENTS.md、docs/README.md、docs/plans/refactor/plan.md、docs/plans/refactor/status.md、产品契约和目标架构。随后按当前阶段读取相关规范，检查实际工作区与已完成证据，从未完成部分继续，不重新生成一套同义计划。

目标是完成 R0–R7：保留既有社区功能、游客浏览、认证暂停与匿名隐私，把项目迁为单仓库下有明确模块所有权、前后端严格 TypeScript、共享运行时契约、受检查的依赖边界、独立可部署产物和可复现验证流程的工程。同步完成计划列出的权限、消息同步、会话隔离、幂等、计数、通知补偿、草稿及生命周期缺陷修复。

我授权你在既定产品和架构边界内自主选择实现细节、依赖版本、构建方案和文件拆分，修复发现的问题，补充必要 ADR 与测试。普通工程选择不需要反复问我。保留所有已有未提交修改，将它们纳入基线；不要恢复到旧 HEAD 丢失游客功能。

按 R0→R7 推进，以可验证业务切片交付。第一项完整迁移样例是消息模块。新接口必须有 schema 和错误语义，旧接口使用薄兼容层并复用同一业务实现。架构约束通过自动检查执行，不能仅留在 AGENTS 或 Markdown 中。

每阶段满足退出条件后继续下一阶段。不要停在空骨架、少数示例模块、仅目录搬迁或只通过类型检查。不要用 any/排除目录、删测试、放宽权限、假造云端结果、清库或恢复邮箱开关来获得表面完成。修复源码形状测试时保留等价或更强的行为保护。

完整准备 R8 的隔离环境与设备验收、迁移和恢复步骤；如果任务环境已经明确提供相应测试环境和工具，执行真实验证并记录结果。没有所需访问能力时完成其余本地工作，列出精确补验步骤与前提。此 goal 默认不包含正式环境发布、清理真实用户数据或恢复邮件服务。

依据 docs/governance/quality-gates.md 完成验收，区分本地检查、隔离云环境和真实设备证据。记录支持版本、包体/调用成本、迁移兼容与未验证事项。只有 R0–R7 完整落地才报告本地重构完成；R8 未通过时明确说明还不能据此认定可上线。

将状态、证据、暂留兼容层、真实阻塞及下一步持续维护在 docs/plans/refactor/status.md。上下文压缩或任务恢复后，先核对该文件和实际代码继续工作。不要不断扩写计划替代实施，也不要把聊天记录当作唯一进度来源。

最终交付完整可运行代码、统一检查/构建入口、必要数据迁移和回退工具、更新后的现行文档、验收证据及清晰的外部待办。最终说明保留了哪些功能、修复了哪些风险、哪些检查真实通过，以及哪些平台/上线条件仍待验证。
