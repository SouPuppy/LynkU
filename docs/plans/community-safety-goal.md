# LynkU 上线保护实施任务

状态：**已设计、待用户启动 goal 后实施**。2026-09-21。本文件只给执行顺序、边界和可直接使用的任务指令；完成状态只记 [refactor/status.md](refactor/status.md)，不在本文维护第二份进度表。

## 1. 唯一实施目标

在现有 LynkU 上补齐协议与隐私、微信自动内容安全检查、举报与个案处置／申诉、私信防骚扰、注销与个人信息权利、关于和备案展示，达到可以交付验证的工程状态。保持校园论坛核心功能和已有账号／认证；**不做人工预审、不增加外部审核商／通用 AI、不做旧协议兼容**。

三份权威设计分别负责不同内容：

- [产品与页面](../product/community-safety.md)：默认行为、权限、依赖上限、CS01—CS12 验收。
- [完整协议与短文案](../product/community-policies.md)：实际页面正文、公开字段与唯一保留表。
- [技术契约与迁移](../architecture/community-governance.md)：接口、类型、集合、事务、作业与迁移。

架构取舍见 [ADR 003](../architecture/decisions/003-community-safety.md)。早期审查与办事手册作为依据保留；其中任何“逐帖人工审核、长帖人工批准、候选发布队列”建议均被用户最新决定取代，不实现。

## 2. 执行前核对

1. 读取仓库 AGENTS、文档入口、当前唯一状态与本任务设计。先检查工作区差异；其他任务正修改身份、帖子、评论、通知及页面 feature，保留并复用已完成成果，不能覆盖或重复造轮子。
2. 核对真实源码、scripts、schema 和云配置。已有通知读取过滤修复不能继续当作未修的显示泄漏；存量删除和恢复问题按代码再确认。
3. 记录当前账号与认证保留条件，分清代码／数据／云部署授权。不要以“无旧协议兼容”为由删除既有用户。真实迁移先验证备份、保护对象和目标环境；禁止清空整个正式库。
4. 从实际微信后台／已授权配置核对可读取资料。用户已备案，原文“浙CP备2026058998号-1X”；只核对展示，不能将没查到搜索结果当作要重办备案。缺完整主体姓名或合同资料时完成其他开发，在发布材料中标出真实待核字段，不反复提问普通设计选择。

## 3. 按依赖实施的可验收切片

每片包含契约、实现、相关页面、必要迁移和行为证据。能并行的模块并行，跨模块提交边界统一后集成。遵守既有 R2—R8，不启动另一套全项目重构。

| 顺序 | 交付内容 | 依赖／完成条件 |
|---|---|---|
| 1：共同基础（R2/R3） | 新协议版本、严格 DTO、内部 accountId／公开 userId、统一生命周期与写入屏障、动作策略；修订配置 schema 与公共文本产物 | 旧账号认证不变；匿名映射不公开；旧协议明确拒绝；新函数独立构建验证路径设计正确 |
| 2：协议与权利入口（R2/R6） | 可离线阅读的四类规则、首次告知、版本凭据、互动确认、关于／联系方式／备案；隐私请求入口与管理受理 | 无预勾选；拒绝仍可公开浏览；直接调用不能绕过；同意不等于学校认证；缺定稿字段只阻止正式发布，不阻止本地开发 |
| 3：自动安全检查（R3/R4） | 单一微信适配器、全文分段、输入绑定、预算／总时限、发帖／评论／修改／昵称／私信接入、旧词表放行和解除 flag 后门退出 | pass 直接提交，无人工待发布队列；review/risky/unavailable 不公开本次内容；失败保留输入；响应丢失以原 requestId 确认 |
| 4：举报与自我保护（R2/R4/R5/R6） | 受理回执、最小工作台、处置／审计／结果通知、申诉、接收偏好与跨匿名来源屏蔽 | 个案处理有真实效果和回执；角色越权失败；匿名和举报人不泄漏；发送与拉黑／禁言并发正确 |
| 5：注销及数据生命周期（R2/R5/R6/R7） | active→closing→closed、18 集合及新增集合清理、本人副本／权利执行、按保留表清理、本地失效、邮箱释放、新加入隔离、备份删除重放 | 不以提交工单冒充完成注销；迟到写入和 outbox 不能复活；新账号不认领旧会话；保留例外按范围限制 |
| 6：集成与交付（R7/R8） | 全流程检查、直接切换迁移包、真实平台与设备验证、配置／权限／timer 读回、运营说明及剩余条件 | CS01—CS12 对应证据；本地／云／设备分别报告；正式送审包与实际功能一致；不静默正式发布 |

注销所需身份和权限基础必须在第一片就纳入设计，但不为了先做注销而暂停独立的页面／自动检查开发。第七个 governance 云函数只承载举报与个案治理；同意、注销和隐私请求仍由 identity 拥有并经 users 路由。分包是小程序内的必要受控页面，不扩展成运营网站。

## 4. 不能省略、也不能扩大

### 必须做成真的

- 普通用户直接调用云函数也不能绕过最新协议、认证、所有权、禁言、注销或拉黑；不能只隐藏按钮。
- 公开 DTO 显式映射，匿名真实身份和举报人不进入普通响应、日志或通知。
- 自动检查在数据库事务外；最终写入重新验证精确正文、版本与当前资格。平台异常不以词表放行。通过后直接发布，管理员不参与正常链路。
- 超时返回区分“确定未提交”和“结果未确认”，同一逻辑操作重试不重复内容、计数、未读或通知。
- 所有删除传播到正文、作者快照、通知／会话摘要、本地缓存及迟到任务；个人信息副本只能返回有权获得的数据。
- 真正的投诉仍要有人处理；可以低频按个案处理，但不能以“不人工审稿”删除举报受理和处置能力。
- 新代码严格 TS、业务不依赖 wx／SDK、每个集合唯一写入所有者、工作流通过窄接口；各函数单独上传仍包含完整依赖。

### 不扩展

不做旧客户端适配器、双写、长期双协议、旧接口 fallback；不做 JWT／第二登录；不重办已完成备案；不换 AppID／环境；不重置学校认证；不添加电话／身份证／GPS／上传／支付／广告；不购买或接入新审核商、通用大模型、外部任务队列或微服务；不建设候选审稿库、长帖人工复核、审核异步 worker 或人工代发私信。

年龄保护、IP 属地和供应商披露按真实可验证能力实现；没有真实数据来源时不能编造已核验年龄、地点或合同。重大外部事实只形成一份最终待核单，不能反复打断普通开发。

## 5. 验证与交付格式

已有完整本地命令为 `npm run check`，按当前 scripts 实际运行；若增加发布文本、迁移或配置检查，将其接入真实检查链并验证失败样本。不能仅靠源码字符串证明权限、审核或注销正确。

重点行为覆盖见产品 CS01—CS12 和技术设计，使用本地合成 SDK 边界测试错误与并发，微信真实检查只用未发布账号额度内的小批测试。G3 必须补真实事务冲突、每个函数的 openapi 权限、超时、ACL／索引、作业租约／恢复；G4 记录真实设备、两账号、普通／匿名互动及注销后重进。不存在隔离环境／所需身份时保留明确未执行记录，继续所有不依赖它的实现，不用 mock 冒充平台通过。

真实迁移采用维护窗口：备份并验证保留对象→停旧写→映射与索引迁移→部署配套新代码→全量核对→启用新写→删除旧路径。只保留一个业务事实来源。恢复也要是一套一致且安全的代码／数据；无法安全恢复时停写，不为恢复可用性重新放开已修复漏洞。

交付包含实际代码／测试、生成产物核对、带 dry-run 和检查点的迁移工具、最终页面文案、运营者操作说明、唯一状态证据及真实剩余条件。源码提交验收与正式公开发布分开：goal 不得宣称保证微信过审，不替运营者作实名声明，也不在未获明确授权时提交审核或公开发布。
