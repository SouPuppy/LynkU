## 本地启动

1. 使用 Node 24.21.x，在 LynkU 根目录执行 `npm run setup`。
2. 微信开发者工具导入 LynkU 根目录，AppID 为 `wxba2bcb0c71a5f33d`，基础库为 3.17.3，使用 TypeScript、Skyline 和 Glass-Easel。
3. 云开发选择 `cloud1-d7gifgdpb8ad0ab8e`。云函数根目录为 `dist/cloudfunctions`；只有 `npm run build:cloud` 生成的产物可部署。
4. 编译后等待微信身份恢复，进入首页。身份失败时可重试或浏览公开内容；未认证账号仍是游客。

`npm run setup` 不修改云端，不建立账号白名单，也不打开邮箱认证。公开配置只改 `config/project.json`，随后执行 `npm run configure`。

常用入口：`npm run dev` 打开项目；`npm run deploy:wechat` 完整检查并通过当前 AppID 的微信 CLI 部署六个函数；`npm run demo:preview` 编译预览并生成 `dist/demo/preview.png` 和包体报告。CLI 路径可通过 `WECHAT_DEVTOOLS_CLI` 指定，端口可通过 `WECHAT_DEVTOOLS_PORT` 指定；命令会校验目标环境属于当前 AppID，并对平台返回的部署失败显式报错。

开发者工具开启自动化（`cli auto --project <仓库绝对路径> --auto-port 9420 --trust-project`）后，运行 `npm run demo:verify`。它用真实微信运行时检查 AppID、账号恢复、公开读取、未认证私有读拒绝和页面导航，报告写入 `dist/demo/smoke.json`，失败返回非零退出码。它不会把游客改为认证账号，也不会写帖子/私信。当前模拟器使用的微信身份会通过正常 `users.ensure` 首次建立未认证账号。

该检查也要求 schema 中所有 admin-only 集合拒绝客户端直接读取；网络错误或集合缺失不算通过。部署代码不代表云端超时、权限和凭据已配置，须逐项核实真实设置。`npm run cloud:inspect` 核对集合和索引，`npm run cloud:init` 续跑受控初始化；两者都不应用数据库权限。

## 演示顺序

| 步骤 | 观察结果 |
|---|---|
| 冷启动 → 首页 | 自动获取真实微信身份；分类和帖子可读取；空库有明确空态 |
| 搜索 → 分类 → 帖子详情 | 页面可进入，公开内容脱敏，失败可重试 |
| 我的 → 设置 | 能看本人资料；名称一致为 LynkU |
| 游客打开私信/发帖 | 引导学校认证，不请求无权读取的私人数据 |
| 已认证账号发帖/草稿/评论 | 成功回到列表；重复提交不产生重复数据；草稿冲突保留输入 |
| 两个已认证微信账号私信 | 独立会话、未读、已读及前后台恢复正确；匿名来源不泄露身份 |

最后两步必须使用真实完成学校邮箱认证的账号，或独立自动化隔离夹具；不能把真实微信游客在数据库里直接改为认证账号来演示。

## 环境及数据边界

LynkU 新环境与 Lucky 旧环境相互独立。旧账号、认证、帖子和历史私信不会因迁文件自动转移；原数据及私人备份保留。身份迁移需要可验证的跨 AppID 关联，不按昵称或邮箱前缀合并。

users 已配置有效服务端邮件凭据，验证码和事务绑定通过 Mailgun 不投递测试模式验证后，公开配置中的邮箱入口已启用。测试不代表真实收件箱投递和真机绑定已经验收。凭据不进入 Git。

完整本地检查为 G1/G2；云端集合/索引/权限、真实 SDK 事务与设备交互分别是 G3/G4。发布体验版和正式审核是独立步骤，本次初始化不自动提交审核。
