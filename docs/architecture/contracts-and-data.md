# 接口、数据与一致性规则

状态：目标规范。字段的最终 schema、集合及索引由实施阶段落地；本文件确定不能省略的语义。

2026-09-21 上线保护的新协议、生命周期／同意／屏蔽／个案治理与数据清理，按 [治理技术设计](community-governance.md) 实施。用户明确不兼容旧协议，历史段落中 v1/OPENID 别名只描述旧实现，不构成继续保留要求。正常内容同步自动检查通过就提交，不建设人工预审候选库。保留表以 [协议文案](../product/community-policies.md) 为唯一目标来源，不能把“同步记录到期”误用于兼作聊天历史的 messages 正文。

## API 边界

1. 按业务动作组织请求、响应和错误 schema。schema 是运行时校验和 TypeScript DTO 类型的同一来源，避免两份手工维护的字段定义。
2. 每个动作定义身份要求、输入上限、输出可见性、幂等/重试语义和分页方式。可选字段的缺省、清空和不修改必须明确区分。
3. 写入输入拒绝未知或越权字段；数据库读出的异常记录在适配边界识别。客户端响应解码允许约定内的向后兼容新增字段，但不能把完整未知字段对象传播到页面。
4. 错误使用稳定 code、可展示 message、请求标识和必要的 retryAfter 等结构化元信息。错误内部原因只进入脱敏诊断日志，不能把 SDK/邮件商原始错误直接展示给用户。
5. 新时间字段使用 UTC ISO 字符串；内部比较使用明确时间类型。旧 Date/数据库时间对象只在兼容层转换。资源标识与时间游标不可混用。
6. ID 不是授权凭据，拿到会话、帖子、草稿或用户 ID 后仍须校验访问权限。

## 公开标识与身份 DTO

- 新协议使用稳定、不可由 OPENID 直接推导的公开 userId；identity 维护映射。迁移必须验证唯一性与历史链接兼容，不批量重写既有所有权字段来凑新格式。
- 普通 PublicProfile 只包含展示必要字段；SelfProfile 才包含本人的认证相关信息；邮箱和认证记录不能进入他人资料、作者摘要或私信对端 DTO。
- 匿名 DTO 使用专门的判别类型，只携带显示身份与受限上下文标识；禁止从普通作者类型展开再删几个字段。
- 兼容期 v1 可能继续接受/返回历史非匿名 OPENID 字段，必须标记为旧协议债务并限定退出条件；匿名身份泄露不属于可保留的兼容行为。
- 每种 DTO 以明确字段构造，不将数据库记录展开到响应、日志或页面状态。

## 协议演进

当前原型采用直接切换：可以重新设计云函数与 action，由唯一部署清单同步构建和更新调用者，不为旧客户端维护接口兼容层。函数名是否保留由职责边界决定。

验收覆盖配套的新客户端与新服务端；切换期间允许维护窗口，停止旧写入入口。版本不匹配时明确报告升级或暂不可用，不静默调用废弃端点。

切换前备份必要数据和部署产物，验证新构建、schema 与保留账号；切换后核对实际读写及权限并删除旧入口。失败恢复是恢复一套一致的代码和数据，不是长期运行双轨业务。正式上线后若需要兼容已发布客户端，另行制定版本政策。

## 幂等和并发

| 操作 | 必须保证 |
|---|---|
| 发帖/评论/私信/初次草稿保存 | 客户端为一次逻辑操作生成稳定 requestId，网络重试复用；服务端按主体+动作+requestId 去重 |
| 同键异内容 | 规范化负载摘要不同则返回冲突，不能错误复用旧成功结果 |
| 重复请求 | 返回原资源/结果，不重复计数、扣限额、生成通知或发送外部请求 |
| 资料/帖子/草稿更新 | 使用 expectedVersion 等机制或经验证的顺序策略，旧写入不能无声覆盖新写入 |
| 删除/已读/事件消费 | 在授权之后幂等处理；已读位置单调前进 |

幂等记录必须与业务提交具有原子关系。事务提交后响应丢失，应能查询同一操作的结果；不能仅用进程内 Map 或按钮 disabled 去重。幂等保留窗口与清理策略必须写进 schema/runbook，不能早于允许的离线重试窗口。

认证查询故障与“未认证”是不同错误；限流存储故障与“超额”也是不同错误。鉴权不可故障放行。目标限流故障策略：创建内容、私信、邮件发送等可能放大成本的操作返回可重试服务不可用；浏览可按有界降级策略继续；草稿云保存失败必须保留账户隔离的本地恢复。此为对现有全局 fail-open 行为的有意修正，需同步测试与界面提示。

## 分页与同步

验证码发送使用 TS sendSchoolVerification：账号维度 60 秒冷却及每小时 5 次配额在 email_send_limits 中事务预留，失败发送同样计数，事务失败不能调用邮件服务。email_verifications 改为每个微信账号一个文档（owner 哈希），新请求替换旧挑战；generation 防止旧请求的成功/失败回调覆盖新挑战和 email_pending。仅服务商接受后、且当前 generation 仍匹配，才把挑战标记为 sent；失败标记 consumed/failed，不保存验证码明文或供应商错误正文。初始化集合只能通过发布迁移，不再在业务请求里创建集合。切换时旧 owner+email 挑战不再可用，用户重新获取验证码；已有账号及已完成认证保留。邮件已投递但状态写入失败时，客户端必须显示未确认，不能把该挑战当作已确认发送；过冷却后可申请新码。

邮箱认证确认使用 TS confirmSchoolEmail：账号、验证码、目标邮箱归属在事务内读取，错误码次数提交后才向调用者报告失败，5 次上限不能由并发绕过；仅 sent 且未过期挑战可首次认证。成功原子更新 users、消费挑战并写入 email_claims，归属文档键为规范化邮箱的稳定哈希，其他微信账号不能覆盖。同一成功挑战重试且当前账号仍绑定该邮箱时返回已确认资料。更换邮箱时读取并释放旧归属；事务先读后写。已有认证账号的 email/verified 必须先迁入 email_claims，当前额外查重查询用于保护这些账号，不能替代归属事务。部署前须建立该私有集合、核对历史唯一性并停用旧确认路径，禁止重置既有认证。验证码发送冷却/状态并发和实际云端验收仍未完成，入口暂不开放。

作者投影更新在数据库写入条件中检查 owner、非匿名、目标快照版本缺失或小于来源版本；不能用更新前读取代替版本条件。来源账号版本必须是非负安全整数；新帖子和帖子修改携带来源 profile_version，评论及通知沿用公共作者快照版本。源版本缺失的旧账号需要迁移，不能悄悄按零处理。此约束防止已存在快照被迟到低版本任务覆盖；某内容在最新投影完成之后才由陈旧 Principal 创建的情况仍需补充刷新机制，不能据此声明作者快照已完全一致。

`users.updateProfile` 已使用 TS 事务应用：只允许规范化昵称/头像，事务内重新验证账号归属与私人 DTO；有变化时，更新账号与写入 profile_outbox 必须在同一事务。profile_version 从非负安全整数递增，字符串、负数和溢出拒绝写入；新账号初始化为 0，已有缺失值需受控迁移。相同当前内容重复提交不产生新版本或事件。并发不同修改采用事务提交顺序覆盖同字段，未提交字段保持原值；此接口尚无客户端版本冲突提示，不能声称具有乐观锁保护。提交后可尝试投递事件，投递失败不得把已提交资料报告为写入失败；可靠调度、版本条件投影和积压告警仍需完成。

`users.ensure` 只识别或初始化微信账号，不承担资料修改或读时 schema 修复；传入 nickname/avatar_url 被拒绝，修改资料走 updateProfile。已有账号按可信 OPENID 查询并保留原文档 ID、认证与角色；真实查询错误不进入创建分支。新账号 ID 为 `stableDocumentId('account', OPENID)`，事务内先读取该文档，存在即返回，不存在才写入默认未认证账号。事务结果再校验归属并映射私人 DTO。发布前必须核对 users 的 OPENID 唯一索引、修复旧 schema 缺陷、停止旧随机 ID 创建入口；新旧创建入口不能混跑。不得以初始化为由重建或清空既有账号；缺失旧字段由单独可审计迁移处理。users 各路径已改用不吞查询异常的方法，查询失败不能伪装成账号不存在。

公开账号资料使用独立 `PublicProfile` 契约，仅允许微信标识、昵称、头像和 ISO 注册时间。users.getProfile 验证目标 ID，查询故障返回错误而非 null，只有确认无记录才返回 null；客户端验证返回 ID 与请求一致并丢弃旧会话结果。作者页面不伪造不存在的用户；帖子统计使用同页公开实名帖子查询的 total，读取失败保留不可用状态，不伪造零。作者资料及列表响应在页面隐藏/销毁后失效。

账号私人响应使用共享 `SelfProfile` 契约，和数据库记录/公开作者卡片分离。users.ensure、updateProfile、verifyEmailCode 在服务端先校验账号归属、规范化时间，再显式映射允许字段；不返回数据库 `_id`、投影版本或未来新增内部字段。客户端同一解析器用于自动身份结果、私人资料写入结果和磁盘缓存恢复；时间为 ISO 字符串，认证标记不做真假值强制转换。资料修改与认证结果必须匹配当前账号及会话代际。损坏缓存只尝试读取一次并尝试清除，不靠重新读取残留缓存恢复身份；后续由自动微信身份请求恢复。缓存校验只保证数据结构，服务端仍独立校验所有权限，缓存不能充当授权凭据。

`posts.listMine` 仅允许已认证调用者读取自己的 published/flagged 帖子，忽略客户端提供的所有者信息。请求使用 `limit`（默认 20，上限 50）与 `cursor`；拒绝旧 offset。按 `(created_at DESC, _id DESC)` 查询下一页，返回 `items/total/hasMore/nextCursor`，游标绑定当前账号并对应本页最后一项。多取一条决定 hasMore；total 是独立读取的当前总数，不代表事务快照。翻页期间的新帖子刷新后出现，已删除/隐藏帖子不保证继续出现。公开列表及搜索仍待迁移到稳定游标，不能据此声称所有帖子查询已经完成迁移。

私人列表使用 schema manifest 中 `(_openid, status, created_at, _id)` 索引；索引声明不等于已在云端创建。客户端只在成功时推进游标，重试复用失败页游标；刷新重建列表，换账号清空私有状态，隐藏页面后丢弃迟到响应。匿名条目即使属于本人也不输出真实作者 ID。

- 静态历史列表使用稳定排序和不可混用的游标，至少有唯一的第二排序键；服务端限制单页大小，不允许用户请求无限全量读取。
- 游标包含版本及查询作用域信息，并校验与当前筛选/会话一致；它不提供授权。游标损坏、过期或超出保留范围返回明确的重新同步信号。
- 静态历史分页与可变状态同步是两种协议。仅把 `updated_at` 改为 `(updated_at, id)` 不能自动证明并发写入、同时间回写和已读更新无遗漏。
- 消息目标优先采用**每会话单调递增的变更序列及可重放变更记录**：消息发送、读取状态等客户端需要的变化获得有序版本，消费游标指向已经成功应用的版本。实现前验证事务竞争、批量写入、索引及保留成本；若更换方案，用 ADR 和对抗测试证明同等完整性。
- 客户端先验证响应、合并并应用结果，再提交游标。某页失败时从最后已应用游标重试；重复交付允许且必须可去重，不能丢失变更。
- 初始快照到增量流须定义一致的交接水位。并发变化不能掉在“快照完成”和“开始轮询”的间隙。
- 历史消息记录与同步变更记录分别保留。变更日志清理后，过期游标触发有界快照重建，不能返回空结果假装同步完成。
- 评论支持分页加载父评论/回复及增量失效刷新；不在每轮刷新中递归读取全部评论。

## 会话、未读与投影

普通会话按参与者确定独立会话标识；匿名会话还包含来源与发起上下文，不能与普通会话共享查询条件。会话成员关系是授权依据。

建立会话目录/成员状态，列表从完整会话索引分页，不扫描固定数量消息聚合。读取位置、总未读与会话摘要有明确来源和可重建逻辑；计数缓存不能成为唯一不可核对的事实。

目标已读语义为“截至客户端确认已读的稳定位置”。并发发送与 markRead、重复 markRead、多个设备读取时未读数须收敛到基准事实；不得用未加版本保护的 count 后 set 清零覆盖新消息。

## 事务事件与补偿

跨业务异步副作用采用持久化 outbox，不要求引入外部消息中间件。业务提交和待处理事件一起提交，消费按至少一次交付设计。

事件包括 eventId、type、schemaVersion、发生时间、聚合标识/版本与最小必要负载；避免把完整正文、邮箱、匿名映射复制到通用事件。通知预览等确需字段限长并限制保留。

消费有租约/认领、重试次数、退避、失败原因、去重和最终失败处理；处理乱序资料更新时不得覆盖较新版本。设置受控调度入口，不能把内部消费动作暴露给普通用户调用。

发布成功但通知生成失败，不回滚已发布内容或要求用户重发。补偿处理可观测且可手动重放。关闭旧读时回填前，须验证新投影追平和后台补偿真实运行。

## 已实现的评论与补偿协议（LynkU）

评论 DTO 使用显式映射与运行时校验，时间为 ISO 字符串；匿名、屏蔽和删除状态不输出真实身份。列表按 created_at、_id 稳定排序，增量按 sequence 递增；任一数据库读取失败必须失败整个响应，不确认未完成的游标。

通知和资料 outbox 分别读取已到期 pending 与租约过期 processing。事务认领递增 attempts，完成事务要求 status=processing 且 attempts 仍属于当前工作者；迟到工作者不能覆盖新租约。通知使用确定性 ID 的事务式首次创建，重放不清空 read。调度来自平台 TRIGGER_SRC=timer、无微信 OPENID 且精确 trigger 名匹配，每分钟运行；客户端事件字段不能授予调度权限。投递失败保留可重试记录并使该次调度失败，后续继续重试。

新增索引为两个 outbox 的 status/lease_until，以及 comments 的 post_id/status/created_at/_id。初始化日志按索引定义摘要识别变更；本轮只补齐新索引，不清空集合或删除旧非冲突索引。触发器创建与云代码部署分别验收，官方微信部署 CLI 不保证应用超时或 timer 配置。

## 数据迁移流程

每个迁移必须有版本 ID、源/目标 schema、执行环境、dry-run、检查点、可重复执行策略、核对查询、失败恢复和备份/回滚说明。

当前原型默认顺序：备份并核对保留对象 → 停止旧写入 → 归并/重建数据与索引 → 核对唯一性、权限和所有权 → 部署配套版本 → 实际验证 → 清理旧入口。用户已授权删除或重建原型集合及冗余记录；已认证账号、指定测试账号与微信关联必须按产品契约保留，不能用全库清空跳过这些要求。不要求兼容读写或双写过渡。

回填需涵盖分页、同时间数据、脏记录、重复执行和并发新写；不能把“当前扫描上限以内相等”当作全量一致。双写如不可避免，明确唯一事实来源、失败补偿和移除条件；禁止长期两套业务源。

建立索引/权限 manifest，与 schema 版本一起检查。唯一约束不能用“先查再插”替代。云端不支持的事务/索引语法应在隔离环境验证并调整设计，mock 不能证明平台支持。

## 数据生命周期

### 管理端用户列表

`admin.listUsers` 每请求验证可信 Web 身份与 `users:read` 能力。请求为昵称字面子串 `query`（最多80字符）、认证状态 `verification`（all/verified/guest）、`limit`（1–50，默认25）与可空 `cursor`。服务端先筛选，再按 `created_at DESC, _id DESC` 查询 limit+1 条；游标绑定昵称和认证筛选，改变筛选必须从首页开始。只返回显式用户摘要与 nextCursor，邮箱脱敏，不返回 OPENID 或匿名关联。列表不构成历史快照：翻页期间改变昵称／认证状态的账号需刷新首页重新获取。

上线前应用 users 的 `(created_at, _id)`、`(verified, created_at, _id)` 索引，并验证实际 SDK 的 Date 比较、同时间分页与昵称正则字面转义；不为此重建用户或修改认证。昵称子串查询可能扫描匹配项，需要在实际规模测量查询延迟；本地有界返回不代表云端性能已验收。

### 管理端帖子列表

`admin.listPosts` 每请求核对content:read。请求status为published/hidden/flagged/deleted，默认published；query仅搜索标题字面子串，最大80字符；limit为1–50，默认25。使用状态/搜索作用域游标及 `(created_at DESC,_id DESC)` 排他分页。服务端校验数据库排序与筛选结果，匿名字段非布尔则失败，不猜测实名。公开DTO排除真实作者ID及作者快照，匿名名称固定；deleted记录标题／作者固定为删除占位，不支持标题搜索。数据库仍需按保留策略执行实际删除，列表脱敏不能替代清理。复用posts的status/created_at/_id索引；真实SDK查询与搜索性能尚待平台验证。

管理帖子详情通过 `admin.readPost {id}` 每请求核对 content:read 并读取当前记录，返回显式摘要、content和updatedAt；删除／缺失记录统一NOT_FOUND，记录ID不匹配拒绝。原始作者快照及匿名映射不进入响应。网页使用 `#content?post=<encoded-id>` 深链接与shadcn Sheet，正文作为React文本节点显示，不解析HTML。详情刷新重新请求并清除旧正文，关闭／切换／退出后的迟到响应不再渲染；未加入后台自动轮询，因此打开期间发生远端变更仍需刷新。

### 举报案件结案

`governance.listReports`使用可信账号与账号作用域游标，按字符串createdAt与_id倒序查询limit+1，默认25／最大50；跨账号游标拒绝，投影仅包含本人reportId、状态、版本、结论、理由、时间。客户端“我的举报”不持久缓存列表，隐藏／销毁／身份变化丢弃迟到响应。该入口提供主动查询，不等于结果通知已送达。

remove_comment结论要求targetToken，来自readComment的当前正文／匿名状态／帖子与父评论关系摘要。服务端在事务内复读目标并比较摘要，再清空正文与作者快照、保留deleted占位、减帖子评论数并追加同序列删除事件；与案件／回执／审计同事务。现有评论无编辑接口，不人为猜测revision；后续任何可编辑字段必须纳入摘要。删除所属帖子后不提供该评论预览。此操作目前无自动恢复入口，申诉及合法保留证据仍待接通。

新增hide_post结论：请求另含targetRevision，必须来自当前帖子预览；只允许post案件且目标仍published并匹配revision。治理通过content的hideReportedPost端口，在同一事务减少有效分类计数、标记hidden、增加帖子revision、记录案件来源并结案／审计。删除、已下架或已修改目标返回冲突，不覆盖作者后续动作。重复相同请求返回原回执，不重复减计数。当前不提供恢复／评论下架，这些流程需要另行实现与验证。

`admin.readCase`与`admin.closeCase`要求governance:write；详情只提供当前案件必要说明，不提供举报人身份。closeCase目前仅接受no_violation与duplicate，必须提交expectedVersion、requestId及公开处理理由。同一事务复核管理成员／业务账号／生命周期，写closed及caseVersion+1、actor作用域回执和审计；相同请求返回原结果，换正文／旧版本冲突。这两种结论不修改目标内容。`governance.readReport`按可信账号核对reporterAccountId，跨账号与缺记录统一NOT_FOUND，只返回本人案件状态与处理结论。用户结果页面、通知、申诉及违规下架处置尚待接通，不能将这两个结案选项视作完整治理。

### 管理端分类修改

`admin.updateCategory` 使用完整可编辑分类预览、managementRevision、requestId和必填理由。content拥有分类字段写入；适配器将可信管理身份、业务账号及生命周期读入同一事务，再进行版本比较、字段更新、`admin_operation_receipts`回执和审计写入。post_count由服务器当前值保留，不接受表单覆盖。回执ID绑定可信Web UID和动作，同请求内容重试返回原结果；换内容或旧版本返回CONFLICT；已撤权不能重放回执。名称唯一性仍依赖categories.name的数据库唯一索引。

该接口尚未部署。启用前在停旧分类管理写入的窗口备份并核对分类，显式初始化managementRevision=0，保留计数；已有revision不得重置。未初始化记录拒绝管理列表读取及修改，不在读路径猜测版本。本地旧categories.update云动作及权限已退出，新建／初始化分类写入managementRevision=0；仍需配套部署退出线上旧入口。网页分类列表已使用带版本DTO并接入编辑侧栏，提供变更预览、原因、回执及冲突状态；结果未确认时固定请求和输入重试，不自动换requestId。回执保留／清理策略、历史分类迁移与事务平台验证仍待完成。

资源分为公开内容、本人私有数据、会话私有数据、敏感身份、临时认证、诊断与审计。每类记录用途、读取角色、保留配置、删除/脱敏传播及备份边界。

过期验证码、限流窗口、幂等记录、事件日志与迁移临时数据必须有清理设计；具体期限由用途、重试窗口和发布政策确定，未确定的生产期限是上线待办。不得在不知道合法保留要求时批量删除真实数据。

本轮实现技术删除/脱敏能力与恢复演练，不擅自推出账户注销产品或认定法律义务已履行。日志和测试数据不得包含真实验证码、邮箱、私信正文、凭据或匿名身份映射。
