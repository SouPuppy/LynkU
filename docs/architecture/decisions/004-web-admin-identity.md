# ADR 004：网页管理端的可信身份与最小部署边界

日期：2026-09-22。状态：采纳，实施中。

## 决定

LynkU 新增 `apps/admin` 作为桌面网页管理端，并新增 `admin` 云函数作为唯一浏览器业务入口。浏览器通过 CloudBase Web 登录建立会话；云函数只从签名调用的 CloudBase 上下文取得 Web UID，忽略浏览器提交的账号、角色、认证或权限字段。

`admin_members` 是由受控运维流程预先建立的绑定。通常绑定同时指向 Web UID 和既有业务账号，每个请求重新核对业务账号的 active 生命周期、学校认证和 `admin` 角色，再按固定角色映射能力。用户决定首发只使用一个专用平台所有者 `admin` 时，允许由环境所有者通过受控运维流程写入唯一 `platform-owner` 绑定；它必须是 `owner` 角色，`account_id` 必须精确等于 `platform-owner:<webUid>`，且不代表、修改或伪造任何小程序账号或学校认证。没有绑定、匿名 Web 会话、已撤权绑定、关闭账号或伪造角色一律拒绝。首个登录者不会自动成为管理员。

网页不直连任何业务集合，也不显示匿名真实身份、全站私信、草稿、验证码、令牌或数据库原始记录。每个后续管理查询或写入继续由所属业务模块提供受控 DTO、稳定分页、版本检查、审计和幂等逻辑；`admin` 仅装配可信身份与权限。

管理前端用 React、严格 TypeScript、Vite、Tailwind 和 shadcn 风格的受控组件构建。CloudBase Node SDK 成为统一云函数运行时的显式精确依赖，以便云包独立安装并从 Web 调用上下文读取可信身份；不依赖微信 SDK 的内部依赖路径。

## 后果

运行任务查询`listOperationTasks/readOperationTask`要求`operations:read`，数据源白名单仅业务通知和资料投影outbox，不接受任意集合名。列表按(created_at,_id)倒序分页、游标绑定任务类型与状态；详情仅返回状态、尝试次数、各时间及白名单错误分类，不返回notification、openid、正文或原始错误。完成任务可能仍有历史last_error，页面明确区分历史错误和当前状态。页面支持深链接、状态刷新和空/故障状态；本接口只读，尚未交付受控人工重试、邮件/审核/清理运行采集，不能据此宣称整个运行模块完成。

`listCases`仅允许`governance:write`，默认查询待处理案件，使用`(updatedAt,_id)`倒序游标、状态/对象类型/目标编号精确筛选，返回`items/nextCursor`，不再返回截断的`cases`数组。游标绑定筛选，最大50条，详情仍走`readCase`；列表只投影目标、原因代码、状态、时间和申诉存在标记，不返回举报人或申诉正文。案件时间沿用ISO字符串，不能与审计集合Date混用。此为实时列表而非快照：处理/申诉可使记录移到前页，页面提供回到首页刷新；单次列表范围及同时间排序仍严格校验。页面URL保存筛选、当前位置和案件编号，结案刷新当前列表，关闭详情保留原筛选。

操作记录使用只读`listAudit/readAudit`，逐请求要求`audit:read`。列表按`(at,_id)`倒序游标分页，最多50条，游标绑定动作、操作者和目标精确筛选；页面筛选、游标和详情编号保存到URL。DTO显式投影动作、时间、目标、管理操作者、理由、结果、请求编号和生效版本，不返回举报人、匿名映射或原始记录。不存在的字段返回null，不推断为成功。举报创建与申诉事件用caseId作为目标，不补充举报人身份。审计时间统一为数据库Date；部署新的governance写入后运行`node tooling/migrate-audit-dates.mjs`检查，必要时`--apply`经完整备份及逐条条件更新转换日期，再部署新的admin查询和网页。不提供旧`events`响应兼容，也不提供修改或删除审计接口。

首次上线前仍需在目标 CloudBase 环境启用并配置所选 Web 登录方式、静态托管来源域名，并通过受控运维流程建立首个 `admin_members` 绑定。这些平台操作不是本地代码或静态页面能够替代的证据。

管理端发布固定到静态托管 `/admin` 路径。`npm run deploy:admin` 先构建，再以 CloudBase CLI 的安全发布上传；随后从远端目录逐项核对入口与已构建资源，不清理或覆盖静态托管中其他路径。该本地核对替代 CLI 3.8.4 对子目录 `--verify` 的错误回滚。

## 成员变更的所有者保护

用户能力限制另由identity用例拥有，管理适配器只注入事务、可信操作者和审计。当前实现将版本及三项到期时间存入users.restrictions，与帖子/评论/私信最终提交读取的同一账号记录竞争；不改变学校认证。能力仅为posts/comments/messages，最多30天，到期按服务端时钟自动失效，解除写null；没有永久封禁或剥夺举报/删除/权利入口。缺restriction字段表示从未受限，有字段却畸形时拒绝放行。此局部账号记录屏障不代表目标lifecycle注销/同意/写入屏障已经完成，后续统一仍需按社区技术契约验收。

设置页的 listMembers/updateMember 仅允许 settings:write。列表有明确100人上限，超出报错而非截断；公开投影不包含Web UID、微信身份或业务账号映射。角色／有效状态修改要求原因、当前版本和操作者作用域请求ID，事务内复核所有者资格并原子写成员、回执和审计。禁止修改自己的资格，必须由另一位有效所有者操作；操作者及目标都进入事务读集，防止两位所有者并发互相撤权后无人管理。独立平台账号只能保持owner角色，可由另一位所有者撤权；业务账号的学校认证和业务管理资格仍按原授权规则独立核验，不由此接口修改。新增或关联账号继续走受控初始化；此接口不创建登录凭据、不开放自动首位抢占。
