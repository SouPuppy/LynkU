# ADR 003：上线保护的最小实现与直接切换

日期：2026-09-21。状态：**采纳为待实现设计**，由用户最新要求约束；不表示功能已实现。

## 问题

校园论坛需要协议、自动安全检查、举报处理、防骚扰和数据权利，用户要求尽快可用、不要逐帖人工审稿、不要高度依赖外部、不要旧版本兼容。现有 CloudBase 同库事务和原生小程序可继续使用；后续用户明确要求增加完整的受控网页管理端，不能把它误缩回单一举报面板。

## 决定

- 正常发布链只接微信要求的自动内容安全检查，pass 后立即提交；不建人工预审队列、持久审稿候选库、自动重试后代发任务或额外审核供应商。完整规范化文本在单次请求中不可变，最终事务校验版本、权限和请求期限。review／risky 阻止本次提交，用户改文或申诉；故障保留输入。已提交但响应丢失由原请求幂等查询澄清。
- 新增薄 `governance` 部署入口及业务模块，只拥有案件、最小证据、处置记录和结果事件。identity、content、interaction、messaging、notifications 仍各写自己的数据；workflows 通过窄 UnitOfWork 编排同库事务，不用跨云函数 RPC 拼事务。
- 原生小程序保留举报／申诉／隐私请求入口；另设受控网页管理端，覆盖内容、用户、分类、治理、运行、审计和设置。网页只经可信 Web 身份和云函数授权访问，不能直连私有集合、全站监控私信或调阅匿名真实身份。
- identity 使用一个 `account_lifecycle` 管理状态、账号代际、限制和写入屏障，不另建平行的 account_access。内部 accountId 与公开 userId 分离，与既有公开标识目标合并迁移；所有派生会话与幂等标识使用内部账号代际，防止注销后重新加入认领旧数据。
- 保留可信微信自动识别；首次持久建号延后至明确隐私告知与确认完成，无独立游客登录。既有账号与认证保留，不能迁移时伪造历史同意。入口权限读取与提交时可撤销权限屏障是两个不同职责。
- 直接切换一套新协议，无向后兼容、双写和旧逻辑 fallback。迁移保留真实用户数据，停止旧写入；退出条件是旧入口确实不可调用，而非标成 deprecated。恢复以一致、安全的版本为单位。

## 理由与代价

沿用现有平台可减少新供应商、凭据、运维和故障点。正常使用不等待人工在线，但仍需处理实际举报、申诉和法定权利请求。微信检查有额度和可用性限制，故障会阻止对应的新内容提交，已有浏览与权利入口保持独立。

同库屏障与新账号标识增加一次必要迁移，但使禁言、拉黑、注销与迟到请求之间的顺序可验证。放弃旧协议需要短维护窗口与清晰升级提示，避免兼容分支继续绕过新权限。保留数据不等于保留旧接口。

## 影响与验收

产品、文本、技术和任务的唯一分工见 [上线保护方案](../../product/community-safety.md)。实施时同步更新动作策略、错误码、schema／索引、配置生成、独立产物和行为测试。CS01—CS12、既有 A01—A15 与 G1—G4 分别提供证据；平台类目或外部办理结果不能从代码通过推导。
