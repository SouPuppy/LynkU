## Scope

Fix the comments cloud function to emit notifications for ALL comment interactions.

### Changes to `cloudfunctions/comments/index.js`

**Before:**
- Only depth=0 comments emit notification (to post author)
- No reply notifications exist

**After:**
1. **Top-level comment (depth=0)**: Emit `type: 'comment'` notification to post author (if commenter != post author) — unchanged
2. **Reply (depth=1)**: Emit `type: 'reply'` notification to parent comment author (if replier != parent author)
3. **Reply (depth=1)**: Also emit `type: 'comment'` notification to post author (if replier != post author AND replier != parent author — avoid double-notify)

### New function: `emitReplyNotification(openid, parentComment, post, content, anonymous)`

- Write notification with `type: 'reply'`, target includes `post_id`, `comment_id`, `post_title`, `comment_preview`
- Same idempotency: 5-minute duplicate check on (type, actor, target.post_id, target.comment_id)
- Fire-and-forget: failure does not roll back comment creation

### Notification card update

The `notification-card` already handles `type: 'reply'` in `TYPE_LABELS` (`'回复了你的评论'`). No frontend changes needed.
